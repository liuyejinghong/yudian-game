一、复算方法（独立实现，纯标准库 csv/json/hashlib/math，未 import 项目模块）
- 帧数 N=数据行数；duration=末行 time_s；avg_fps=N/Σframe_ms*1000（与 measure_baseline.recompute 同定义）
- nearest-rank：升序取 sorted[ceil(N*p/100)-1]，p∈{50,95,99}；max=升序末位；over_33ms=严格 >33 计数
- 全帧保留（含启动尖刺），未删任何帧；另校验列头、frame 连续、frame_ms>0、time_s 严格递增、
  time_s≡cumsum(frame_ms)/1000（六轮最大偏差 ~2.6e-13，内部自洽，原点=Recorder 首帧）
- 六轮复算结果与 foreground/background-compare、summary.json、verification.json、collector-verification.json
  五处记录全部一致（frames/duration/avg_fps/p50/p95/p99/max/over_33ms，零差异）

四、focus-conditions / sequence 受控性：不完全受控，实际偏离如下
1. 后台三轮均有"前台残留"：激活 Finder(exit 0)后 app 仍为 front_pid——bg-1 前1.2s、bg-2 前2.7s、bg-3 前7.5s。
   残留时长与 avg_fps 单调负相关（7.5s→75.0、2.7s→107.5、1.2s→137.5），方向上符合前台相关调频假设；
   但 front-samples origin=外部 Popen monotonic ≠ Recorder 时间零点（文件自述），与 frames.csv 不可对齐，仅作观察不作结论。
2. "焦点 set 返回 0"六轮全部成立但不能证明状态：bg 轮证明（exit 0 后 app 仍前台约2s）、fg 轮证明（0.8s 级点采样，
   间隔内瞬时失焦不可观测）；无任何连续前台证明。
3. 各轮运行前前台 app 不同（28269/75186/21200/37323 混杂），bg 轮运行中焦点落点亦不同（21200/28269/37323/75186），
   环境本底未对齐；fg 轮 before/after front_pid 相同、bg 轮不同（与模式自洽）。
4. temperature 六轮均 NOT_MEASURED；电源均 AC 100%、无热警告（仅时点快照，非连续记录）。
5. compare 工具 limitation 首条"现有证据不含前台/后台…记录"就 compare.py 输入而言成立，但就证据包整体偏保守：
   front-samples/conditions 实际含时点级焦点/电源/热记录（不连续）。
6. 启动帧未删：fg 三轮 max 即 frame1 启动尖刺（72.5/74.5/79.5ms），over_33 名单含 frame1-3/16，符合"不剔除"约定 ✓

五、限定结论（本报告不构成验收）
- 六轮逐轮统计量离线可复现、内部一致、SHA 链完整，作为"逐轮记录"可信。
- 前台组 75.07–77.19 FPS 仅适用于该灰盒负载与该机器当时状态；不含温度。
- 后台组 75–137 FPS 离散系前台残留混杂所致，F/B 差异不可归因；"实际前台约75–77、后台75–137"仅为待复核假设，
  不得作为 expected 使用。
- 本证据包不能证明持续前台、不包含受控实机采样的最终裁决，不代替真实 GUI 测试（与 README/limitation 一致）。
- 本票不改 expected、不领新票；复核建议（供人工决策，未执行）：后台轮改用遮挡/隐藏窗口或在激活后确认 front_pid
  切换完成再进计时窗，前台轮加连续焦点轮询并统一记录两时钟偏移。
