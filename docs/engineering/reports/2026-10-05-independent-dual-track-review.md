# 独立双线调研与诊断：审查归档及路线细化理由

2026-10-05。本文是此前独立研究答复的仓库整理版，具体实施见[双线路线入口](../../roadmap/README.md)。不是逐字聊天记录，也不是本次重新运行游戏的报告。产品已确认、实现事实和建议路线分开；不代替所有者最终视觉或玩法判断。

## 1. 实际证据边界

素材／工程审查锚点为 `16e573b01c0f7700e44224fd0fafb6e1246ea930`。此前研究通过 GitHub 读新交接和固定文件，并在环境成功挂载后使用同基线的两份快照核对原始字节。快照所列20个产研文件、485个美术文件内部 hash 一致；它们是选定快照，不是完整仓库或全部历史。当前 `.app` 仍对应 `3e64e532a3474b2329e52575756c1a79bdac47db` 的工程整平场景。

此前视觉审阅为三关系图＋十四条正常镜头＋四十四张补充状态／角度／近景，共61张唯一PNG，不是287张逐张审完。此前读取14个canonical GLB的JSON／二进制位置和索引、静态变换、网格／材质／动画条目、UV属性存在；14个GLB和42条source.files身份匹配。没有打开Blender、重放连续动画、运行Godot物理／导航／联合性能、运行或重打包用户应用。历史高保真实验未在审阅范围。

本次 PR 只整理文档、细化任务并复核归档登记与可用快照的字节，不把它记成新的视觉或实机验收。PNG和GLB登记见[实际效果审查](../../art/production/review/2026-10-05-independent-review.md)。机器路径清理造成旧文本hash变化，按既有publication说明处理，不误报模型损坏。

## 2. 主要结论

现有地形提交／投影恢复、原生移动和有限到场作业值得保留。下一阶段应把普通玩家操作、低保真正式接入和有限保存前移，让同一个默认应用不断获得实际能力；不能继续累积互不相连的探针，也不能等全系统或全部高保真完成才给所有者操作。

九模块适合作为责任边界，不适合作为九项分别建完再集成的大工程。保留既有 D1—D3 主命名，把上次答复的 M1/M2a/M2b/M3 映射为 D1.0/D1.1/D1.2/D2 的内部检查点；生产切片 P1 横切，发行 R1 另验。具体变化见[联合里程碑](../../roadmap/milestones.md)。

本地模型的关键不确定性在 D1.1 起试验，但不阻塞账本、建设、保存；试验通过必须接真实任务，规则计划加模型解说不算本地委托。高保真则相反：低保真轮廓、尺度、状态和实际游戏用途先过门槛，再让 Astra 做少量代表样本，不整库同时细化。

## 4. 对现有代码的诊断

`prototype/scripts/Main.LiveTerrain.cs` 区分权威状态、投影版本和下一物理帧验证，提交前核占用、故障时暂停并从Current恢复。它证明有限世界改造不只改显示，值得延续；不证明磁盘存档或完整导航。

`TerrainWorld/Actors/GroundPatrol.cs` 的原生MoveAndSlide与订单到达条件，以及 `Main.LevelJob.cs` 的到场／有效作业／提交／物理确认，是比倒计时动画更可靠的起点。但固定目标点追逐不是寻路，按机器人名字前缀和距离选站不是通用能力调度。

下一步参数化有限合法作业范围、能力／工位和真实规则接缝；不将工程的连续三秒／中断清零直接推广为所有工段。已有提交后的地表成果应保留，施工／材料／在途应分别保存。Main应成为组合入口，不继续承载每一种经营事实的特例。

正式模型的静态／活动包络必须校准到实际选择、碰撞、工位和路线；旧代理半径不能因模型导入成功就自动合格。工程默认应用、独立模型预览和未来玩家版本分别认定。

## 5. 经营选择而不是全自动观看或逐工序手操

玩家保留发展方向、位置、优先级、保护物资和风险边界；机器人在授权内补采集、运输、加工、整平、建设和保障前置。扩大供电与扩大加工、靠矿点建与靠保障建、先扩张与保留维修物资，都应通过真实能力／距离／成本影响下一轮选择。

不让模型自己无限决定基地下一步发展，也不故意把它做笨来迫使玩家点每个工序。扩大用地、新增未授权设施、动保护库存或承担未批准风险才再次请求。目标登记不等于保证可达，搜索超时不等于基地失败。

试玩同时观察理解、真实决策和继续经营意愿；关闭台词后仍能说明执行者与等待原因，完成一个目标后能提出下一目标。功能测试只证明规则，不证明好玩；安全成长与风险分支分开，允许随时停止，不用强制首夜受损制造压力。

## 6. 不确定性与直接建设的分界

值得短试验：自动化后的决策价值、自举／保障是否死锁、改地形后的路线／工位、本地候选实际能力和联合负载。每项有固定输入、停止条件、采用结果及正式接入包。

可直接渐进建设：实体ID、资源目录、命令边界、选择操作、统一暂停、磁盘快照和只读状态。无需每项另开一次性概念验证，更不能等万能框架齐备才开放试玩。

本次细化还修正两处容易分叉的地方：矿量权威按既有路线归RESOURCES，WORLD拥有空间／已知信息；M名称不再与D1—D3平行维护。其余产品变化只进入待所有者决定表，不默默删承诺。

## 7. 双线汇合与最终建议

先交可操作场地及最小保存，再交有实际投入和能力后果的自举建设，再贯通真实缺料链、正常保障和下一次发展。之后加入多目标／探索／变化、本地委托／救援和联合验收。每批都由Codex完成Main、导入、默认应用和独立验收，GLM只能提交指定包。

美术优先正常视距、地表成果、选择／工程标记与六类资源，局部修U01载荷和F02功能形态；服务接口先冻结再制作成对状态。少量高保真只有在低保真和真实用途通过后开始；第二件证明流程可重复，再按实际产能扩展。

四维进度分别保留验证、实现／制作、接入和版本验收。失败时修最小受影响部分，保留有效底座。文档、测试数量、文件合并和漂亮独立预览都不能冒称经营体验已经成立。
