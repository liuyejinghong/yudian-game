# 工作项 Spec 模板

> 历史提案（2026-10-03；2026-10-05归档）：空工程起点与启动Spec均为当时记录。工程已经建立，本文不作现役派单合同；当前范围与状态以[产研TODO](../../tasks/todo.md)为准。

> 不应直接交给工人填空后自行实施。由主控填入真实基线与冻结合同并标 READY。

## 识别

- Spec ID / 修订：
- 对应内部版本：
- 状态：DRAFT / READY / IN_PROGRESS / REVIEW / ACCEPTED / BLOCKED
- 风险等级、负责人、独立审查人：
- 准确基线提交与已完成依赖：

## 一个目标

玩家或开发者在什么条件下，能观察到什么新的结果？不要写“完善某模块”。

## 非目标

明确不改的能力、数据和界面。与已有产品规则冲突则停止，而非私自降范围。

## 读取与写入边界

- 最小必读文档/源文件：
- 允许写入的精确路径：
- 禁止修改的公共类型、项目文件、锁文件、存档与集成入口：
- 共享文件唯一写者：

## 输入与输出

填写已经存在的真实类型/资源 ID、合法值域、单位、错误与空值行为。

凡“实现者自行决定接口”仍留空者不得 READY。Spec 例子不是可以随意复制的新公共类型。

## 行为与例子

| 输入/前提 | 操作 | 可观察预期 | 不应发生 |
|---|---|---|---|
| 正常 | … | … | … |
| 边界 | … | … | … |
| 无效 | … | … | … |
| 取消/过期（涉及异步时） | … | … | … |

例子的期望值由合同推导或独立验收提供，不通过运行待测实现来反向生成答案。

## 验收

区分编译、规则测试、集成、实机、真人。写清每项命令是否已存在；不存在时先列为待主控建立，不冒充当前可以运行。

给出正常/负向/回归场景、证据位置、预先确定的通过条件。性能类要指定硬件、负载、分辨率、模型状态、热机条件、采样窗口与未通过处理。

## 交付与停止

准确提交、diff、测试命令与退出状态、日志/截图/记录、剩余问题、回退。

越权写入、依赖缺失、合同矛盾、需要新付费资源、必须改变核心模型时 BLOCKED，交主控。自测通过只进入 REVIEW，不自动 ACCEPTED。

## 派单前检查

- 任务可以由单个边界明确的提交完成吗？
- 工人不理解全项目，也能按合同判断正确与错误吗？
- 有独立于实现者的反例和验收人吗？
- 失败能局部回退，不伤及存档和其他工作吗？

任一关键答案是否定的，先拆任务或补合同，不增加提示词长度来掩盖问题。
