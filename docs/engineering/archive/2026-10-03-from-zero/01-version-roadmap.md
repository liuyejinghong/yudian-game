# 从零到原型、垂直切片与后续版本

> 历史提案（2026-10-03；2026-10-05归档）：空工程起点与启动Spec均为当时记录。工程已经建立，本文不作现役派单合同；当前范围与状态以[产研TODO](../../tasks/todo.md)为准。

状态：建议的内部里程碑，不是排定工期。每次只批准当前版本，详细工作项只展开到当前和紧邻下一阶段。

## 1. 原型必须做，但不是再造一个文字 MUD

视觉参考回答外观；可交互场景回答“是否像在指挥一个地方”；行为原型回答“一项缺料目标能否真实办成”；联合原型回答这些能力在同一台机器上能否稳定运行。

早期使用能区分三类机器人和工作状态的简化三维对象。没有真实执行的场景明确标为交互演示；规则提供者明确标为规则基线。不能用脚本定时改数字、预录视频、仅生成 TODO 或漂亮台词冒充目标委托。

## 3. 工程起点与骨架

推荐候选布局由主控创建并核实，不是当前仓库已存在的目录：

```text
game/                     Godot 应用、场景、UI 与世界投影
src/Yudian.Simulation/     独立模拟数据、规则与确定性执行
src/Yudian.Contracts/      命令、快照与内容边界（唯一写者）
tests/                    规则测试、集成场景与独立验收
content/                  有版本的有限配方/能力数据
fixtures/                 开发与测试档，不是正式开局
scripts/                  实际可运行的构建/校验入口
docs/                     决策、Spec 与证据入口
```

早期不为了“以后扩展”引入微服务、数据库服务器、万能工作流或庞大自研 ECS。热路径优化要能局部替换；工具链/规则/UI 的依赖边界先清楚，目录数量不是架构质量。

## 4. 可复用与可抛弃

可替换：v0.0.2 演示数据、临时相机 UI、孤立性能实验、候选模型适配。它们不能自动升级成正式代码。

优先保留：明确的规则合同、独立验收样例、资产 ID 与尺度约定、经过评审的小型实现、原始性能证据。原型不是所有代码都要扔掉，也不是写了就必须留。

开发存档在正式兼容承诺前可通过显式流程重置，仅限隔离测试数据。不要为清测试数据删除用户真实存档。

## 5. 发版与状态

每个内部版本附：基线提交、准确启动路径、已做/未做、测试范围、提供者模式、演示数据说明、回退方式。

“编译通过”“场景可运行”“行为正确”“本地智能通过”“实机性能通过”“真人喜欢”是六种结论，不合并成一个笼统全绿。
