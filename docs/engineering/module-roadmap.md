# 游戏模块与开发里程碑

2026-10-05｜当前模块框架。依据现役[产品定义](../product/product-definition.md)、[保障规则](../product/energy-return-and-rescue.md)与所有者本轮要求：验证成果应进入游戏建设，不以探针数量代替游戏开发进度。

这是职责划分和版本目标，不是新建一套通用框架。复用 `prototype/` 工程和已有实现；不预建空目录、全模块接口或另起整套工程。逐包状态、派单与接受证据仍只在[产研 TODO](tasks/todo.md)维护；远期范围不因列入路线自动开工。

## 1. 九个游戏模块

| 模块 / 父任务 | 职责与玩家得到的能力 | 现有可复用成果（本日盘点） | 下一步建设范围 |
|---|---|---|---|
| 玩家 UI/UX / GAME-UX | 指挥镜头、对象选择、建造预览、目标看板、库存/供能/健康反馈、暂停与干预；新档与引导 | Main只有工程按钮/状态文字，无正常指挥交互 | D1：镜头/选择/放置/目标与原因反馈；绑定真实模拟，工程按钮移到工程入口 |
| 世界与区域探索 / GAME-WORLD | 地块、矿点、玩家已知情报、勘探、区域权限与通行事实；地形版本 | 单区域地形权威状态、网格/碰撞与Main同步 | D1：有限地图/已知资源/合法范围；D2：获准勘探未知矿点；D3：更广区域与扩张 |
| 资源与生产物流 / GAME-RESOURCES | 有限矿量、采集、加工、库存、货物在途/搬运、投入产出与预留 | 矿点挖低目前只改几何，不产矿；实际资源链未实现 | D1：小型真实采集→加工→运输链及成本；D2：共享资源竞争与取消/重载一致 |
| 建设与设施 / GAME-BUILD | 选址合法性、工程工序、清场/整平、施工投入、设施建成和运行能力 | 单机器人真实整平与地形提交；没有通用设施建设 | D1：复用整平接正式工程，建设成果进入基地能力；D2：取消保留成果/变更重验 |
| 机器人与任务执行 / GAME-ROBOTS | 能力分工、导航/避让、采集搬运施工等执行、任务占用、轮换协作与真实阻塞 | 原生贴地运动、单目标订单与WorkMeter；巡逻不是调度/AI | D1：有限场景可达路径和实际任务驱动；D2：多机/保障协作、冲突与变化；闲置不无目的巡逻 |
| 能源与机群保障 / GAME-SUPPORT | 发电/用电、单机电量、耗电磨损、回充/维修、停机与回收救援、有限服务位 | 尚未实现；需求含约10%常态回充、动态返程预算、零电/零耐久区别 | D1：真实供能、耗电/耐久、充电与维修；D2：变化预算、争用、停机救援及安全/风险分支 |
| 目标委托与规划 / GAME-GOALS | 建设目标、合法前置、预算/保护条件/优先级、计划与重规划、本地能力/提供者 | 固定整平任务不是通用目标规划；T4仍未实现 | D1：有限受支持目标与前置、可解释计划/边界；替身标识。D2：现役本地能力与API共用语义验证、变化/竞争 |
| 模拟时间与存档 / GAME-SAVE | 模拟时间/暂停、版本化保存加载、世界/资源/任务一致恢复、不补算离线收益 | 地形内存Current恢复不等于玩家存档；性能CSV不是存档 | D1即落实统一时间/暂停与可保存的事实边界；D2实际保存/恢复/损坏回退，已有任务不重复扣料 |
| 表现、运行质量与交付 / GAME-DELIVERY | 正式资产状态投影、必要声画反馈、性能/原生运行、版本标识和双击应用 | M01接线、I00校准、工程.app与证据工具；正式资产/稳定预算未完成 | 每个里程碑接入素材与更新实际应用；D2联合性能/正式小样；缺素材挂ART-LINK；商业发行/Windows仍后续 |

模块划分描述职责，不要求一个模块对应一个类、文件夹或agent，也不要求先做完一个模块才能开始另一个。首批仅实现当前版本需要的深度；美术制作仍由美术线负责，产研负责真实导入和游戏状态接线。

## 2. 共享事实边界

先定当前任务用到的少量字段和命令，避免各模块复制一套世界：

- WORLD维护地形、矿点位置/可达信息、区域权限及玩家已知情报；RESOURCES维护矿量、库存、在途与预留账，采集同时关联世界变化，不能改个坑就重复发矿。
- BUILD维护设施实例和工程阶段；ROBOTS维护执行与占用；SUPPORT维护电量/耐久与服务状态，扣用物料经RESOURCES。一次成本、占用或产出只有一个权威提交入口。
- GOALS维护目标、授权与计划；它请求世界行动，不能凭模型输出直接生成资源或健康。UI读取这些事实并发出玩家命令，动画不结算产出。
- SAVE提供统一模拟时间/暂停和持久化边界，保存各模块权威状态；不另建“存档世界”。暂停停止移动、生产、耗电磨损，不等待全部存档实现才落实。未知矿点不向规划器当已知资源开放。

这些是职责约束，具体提交方式随当前包冻结。主控负责资源/权限/关键状态与持久化契约，不先制作万能事件总线、工作流平台或庞大ECS。

## 3. 模块横向建设，版本纵向集成

现状：只有工程底座及固定整平子流程已限定接受，下面三个游戏里程碑均未完成。D1、D2、D3是项目内部开发目标，不是发售版本或日期承诺。

| 里程碑 | 玩家实际能做什么 | 涉及模块与完成证据 |
|---|---|---|
| D1 可操作的经营基地 | 操作镜头、选择对象与位置，下达有限建设目标；机器人执行真实工作，有限材料/供能/维护产生后果；玩家能调整发展或保障顺序，接着下一个目标 | UX/WORLD/RESOURCES/BUILD/ROBOTS/SUPPORT/GOALS/SAVE时间规则/DELIVERY各做最低需要范围，集成同一主游戏并重打包；功能与异常工程复验，理解与持续游玩意愿另取真人反馈。不能以固定按钮/单建筑动画验收整个D1；无存档或规划替身时明确标识，不称完整G1 |
| D2 G1：会把目标办成的工程队 | 缺料能补齐合法前置；多机协作，处理变化与目标竞争；补能维修/停机救援；获准勘探未确认矿点；保存重开仍能继续 | 覆盖产品§14、A01–A24及保障B01–B08的实际范围；真实本地能力、断网、提供者共用语义/API故障边界、正式小样、地形/任务/经济保存一致与联合性能均需证据。缺设备/真实API授权时如实NOT_RUN，不按里程碑名称签G1全过 |
| D3 区域探索与基地扩张 | 从小型基地发展到更多可用区域/矿源与发展组合，持续产生布局/保障/优先级取舍 | 扩展WORLD与已接入模块，逐次试玩控制节奏、信息和规模；详细地图/探索规则待冻结，不预承诺整星球、多层世界、战斗或新产品系统 |

D1内部可先交可操作入口、再交资源/建设、再接保障和经营选择，每次都合并并更新应用。每次交付写清可玩范围，D1整体验收等上述相互关系贯通；不要求攒到所有模块完成才给所有者看到变化。D2的探索为小范围勘探，不必等D3才处理未知情报。

## 4. 验证成果怎样变成开发进度

一个模块可包含多张实现/集成票，分别记录四种证据：

1. **假设/方案验证**：回答一个明确问题，记录采用或调整原因。
2. **实现接受**：当前范围代码与必要规则检查通过；已有ACCEPTED只覆盖原票范围。
3. **主游戏集成**：合并到main、进入普通玩家入口、与其他模块同一事实运行。
4. **版本游戏内验收**：重打包可核版本的双击应用，复验实际玩家步骤；理解/趣味性标记真人反馈情况。

常规任务把实现和主场景接入放在同一批次，只有真实风险或文件归属需要才单独拆探针。确有独立验证票时，交付必须关联**采用结果、接入任务、负责者、目标里程碑**；采用后进入相应建设票，不无限留在“以后集成”。合并代码也不等于当前固定.app已更新。

已接受地形/碰撞→GAME-WORLD与GAME-BUILD；原生运动/订单/计时→GAME-ROBOTS与GAME-BUILD；性能/生命周期工具→GAME-DELIVERY。Main已接入的有限能力保留；导航、资源、保障、目标委托和存档仍须建设。旧报告不重签，不重做底座来制造新进度。
