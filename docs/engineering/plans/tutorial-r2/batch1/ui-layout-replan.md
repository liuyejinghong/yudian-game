# 批1 UI 第二轮失败后的局部重计划

2026-10-14｜两轮真实headless UI检查失败后，按两失败规则先记录、改布局方法，不继续盲试。首轮187项/2失败/1阻断；第二轮762项/17失败/1阻断，exit1、ERROR0；dummy截图NOT_RUN。成功的管理/Esc/读取回滚/真实接线成本等成果保留。

## 已核原因

- 首次建设空蓝图4条失败属于测试前提：BuildModeNullTypeChecks排在已选solar的BuildPlanDraftChecks之后。移到首次建设前，保空蓝图/不整地fallback断言，不重置生产字段。
- 原layout找不到候选已通过恢复测试初镜头解决，但新实际矩形揭示窄窗/高倍率内容溢出：卡片从标题、选址、完整长拒因、成本、供料、自动前置一路堆叠，ConfirmButton最后。1860×939@150确认Y753–819而可视mask末791；1280×800@125确认Y617–672而mask末664。1280@150也失败。外层PlanScroll滚动不能兑现主按钮固定可见。
- 设施pick仍BLOCKED。单次中心射线可能被机器人/侧栏遮挡或取景未到，本轮必须用实际场景投影+真实点击覆盖，不仅范围推断。

## 布局决策（仅PlayerUI owner写）

1. `PlanScroll`保已有节点名/必要消费，但外层不承载超长全部内容滚动；建设侧栏在可用高度内分为固定标题/操作区＋内部可滚成本详情。
2. 固定区从上到下：标题、简洁场址/朝向、完整当前阻塞（必要时有自己的可见小滚动块，不截断拒因）、开始/退出按钮、简短收益与自动前置提示。主按钮先于多行成本与路线，固定区高度必须受实际viewport约束；控制卡内不必要重复文字并可把位置/朝向单行呈现。
3. 成本按行给完整quantity/此计划已有/还需补，处于默认可见内部滚动区域；所有字段可查，长成本/备用供料/电源详情允许滚动。当前阻塞/主按钮无需滚到最底。预算不足时允许成本滚动，不删真实成本或将其放到必须主动展开才看得到的暗处。
4. 同mask覆盖当期三尺寸（1280×800、1920×1080、1920×1200）与100/125/150%；布局合同测试区分固定操作区与内部成本scroll的准确mask，保完整拒因/按钮真正在屏内，不能把失败改成BLOCKED。
5. 管理/确认clamp已本轮通过的结果保；焦点poll gate/Esc/returncontext不退化。顶部警报/活动行不抢世界全部空间。
6. 用正常Control/Container/anchor和最小局部调整，不推翻整体HUD，不改Main、权限、账本、选择规则或数值。设施pick测试通过实际engineinput定位真实对象，若源码picker可证明错误再修该局部。

新证据目录重跑编译及UI合同，不覆盖前两轮。尺寸用真实headless控件矩形，视觉/原生键鼠仍交Codex。未过不得签候选；有新具体失败再返对应局部，不扩大研究。
