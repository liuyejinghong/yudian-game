| 项 | 内容 |

| 依赖 | 定义目录（stableID 清单）冻结 → 权威 DTO 冻结 → HUD 适配才开写；B002 复现独立进行，不阻塞前两者 |
| 未决 | B002 根因未知，复现前不修；D002 是否随口径修复消失待 G001/G002 复验；真人理解失败率未测，不以 AI 首访代签 |
| 验收 | G001 无提示预测→执行→解释一次完整链，不赠料；UI 数据账实一致；预览不扣料；双提交只登记一次；B002 停滞若复现，验同目标恢复，取消旧料再利用不能替代恢复验证；独立新玩家轨验 D001，工程测试不关闭 D001 |

最低改动：

- 物资／配方／建筑最小统一只读定义目录：stableID、显示名与说明、类别、视觉引用、沿用现有计量单位；去掉 [BootstrapConfig.cs](../../../../prototype/scripts/Resources/Core/BootstrapConfig.cs) 的固定数量校验限制；配方 planner 共同检查引用完整性，不只校验 Material 数组（消费方含 [ProductionPlan.cs](../../../../prototype/scripts/Goals/ProductionPlan.cs)）。
- HUD 数据口径／上下文与目标委托理解修复，按 hud-spec.md；现有 7 物资、4 配方、5 建筑数值不动。
- 世界对象选择与结构化投影：当前 HUD 点击只能选机器人/地面，矿与设施不可选；批1 接入 typed Mine/Facility 对象投影与选择，这是 D001 的真实因果入口，不只改文案（投影字段落在 [PlayerContracts.cs](../../../../prototype/scripts/PlayerContracts.cs)，属整合窗口）。
