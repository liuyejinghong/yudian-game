## 1. 首先核对现场

确认远端确为 `liuyejinghong/yudian-game`，记录当前分支、精确 HEAD、工作树状态和本机工具版本。已有其他人的修改不要覆盖。历史 `liuyejinghong/ai-mud` 只作参考，不切入它开展新玩法，不修改旧 PR、数据库、VPS 或账号。

运行文档检查：

```bash
python3 tools/verify_documents.py
python3 -m unittest discover -s tools -p 'test_verify_documents.py'
```

说明当前只有文档与文档工具；不能声称这些命令代表 Godot、模型、图形或游戏测试通过。

## 2. 产品条件不可遗失

Mac Apple Silicon 原生首发，Windows 后续；参考机 M3 Pro 满血／36GB，不是最低配置。实时 3D、RTS 斜俯视；美术主参考 Surviving Mars: Relaunched 与 Anno 2205。

玩家给目标，机器人自动补齐合法前置；看板和世界消费同一事实。清坡、推平、开挖真实保存，碰撞与导航一致。机器人需要能源、耐久和维修；零电原地停机，常态约 10% 回充但需考虑动态返航预算；零耐久需其他机器人送回维修。

AI 不越过保护库存、设备、区域和资源预算。救援者也需要可行的去程和负载回程。场景停机、载荷、恢复与原目标衔接必须真实，不靠传送或免费回电。核心本地模式完整可用，不强迫玩家配置 API 或注册额外账号。

## 3. 按明确指派的一个范围推进

只指定美术时，按已选参考做同场景样张与改造前后对照，不重新提旧像素或军事默认。概念图不叫实机，未经确认不批量制作全部设施。

只指定技术验证时，以 Godot 4 .NET＋C# 为领先候选，固定版本和复现场景；核对 Mac 原生依赖，真实地形／任务／能源耐久／救援／本地 AI／保存的联合负载。较低配置设备拿不到写 NOT_RUN。MetalFX 等超分按专项验证，不把 SDK 下载视为完成，也不把插帧 FPS 当模拟速度。

两线同一场景汇合，形成一个有证据的技术主推荐和资源规范。未经单独指派，不将整个路线自动推进到 G1、EA 发售、付费模型调用或全部资源制作。

## 4. 交付要求

给出提交、改动文件、可重复命令、实际运行结果、未运行项、图形／状态证据、风险和下一处需决定的产品取舍。API 付费、模型权重再分发、资源许可单独记录。禁止密钥、私人数据、模型权重和第三方游戏资产入普通 Git 历史。

技术原型可先用具名灰模档，不能以无限电量、关闭磨损或删除真实地表获得所谓低配通过。模型合法输出被校验通过与实际目标完成分别计分；搜索失败不是证明基地不可恢复。

产品或架构降范围要明确提出，不修改允许列表、删除失败测试或回写历史来制造通过。完成后给可审查改动，不自行合并或部署。
