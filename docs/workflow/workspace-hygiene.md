# 工作区卫生规则

本仓库以 `repo`（main 分支）为唯一日常开发与交付状态。本文只写一般规则，供开发者与 agent 共用，不记录个人机器路径或玩家数据。

## 开发入口唯一

- 「当前开发」是项目同级的入口，指向 `repo`。日常开发与交付都以 `repo` 为准，续做从这里进入。
- 默认只使用 `repo`。任务确需硬隔离时，才临时新建工作树，规则见「临时隔离与收尾」。
- 日常保持 `repo` 在 `main`；合格成果按当前任务已授权的范围审查并集成，不把已有授权再变成重复审批。
- 历史保留的工作树与归档只用于恢复，不在本文展开，也不作为开发入口。

## 临时隔离与收尾

- 临时工作树只为当前任务存在，不在 `.claude/worktrees/` 下长期堆放。
- 登记台账（分支、HEAD、用途、去向）。任务完成后及时集成并收尾。
- 移除须同时满足：
  1. 已集成进 `main`，或经确认不再需要且分支已登记；
  2. 工作区干净，无未提交修改与未跟踪文件；
  3. 无人、会话或进程正在使用该目录。
- 移除前确认台账已更新。移除工作树不等于删除分支，分支删除另行决定。
- 不满足移除条件的工作树保留，待条件满足后再移除。

## 未提交内容先保

- 独有的未提交修改或未跟踪文件，先完整备份，再分类：已验证拟入 `main` 的，按当前授权集成；其余完整保留到恢复目录，并登记路径、基线与恢复方式。未经判断不混入 `main`，也不因陈旧或整理而删除。
- 归档只是备份，不解除未提交内容的保护。
- 未提交内容不代表功能完成，也不代表已合并或已验收。

## 归档不是合并

- 目录归档、bundle 与元数据快照只用于恢复，不代表代码已进入 `main`。
- 代码进入 `main` 必须经过 PR 与审查，整理结果不能替代这一步。
