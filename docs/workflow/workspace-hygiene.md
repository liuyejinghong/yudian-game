# 工作区卫生规则

本仓库使用多个 Git 工作树开发。本文只写一般规则，供开发者与 agent 共用，不记录个人机器路径或玩家数据。

## 开发入口唯一

- 继续开发时，从项目同级的「当前开发」入口进入当前工作树，不从历史工作树或主检出目录直接续做。
- 主检出目录保持其既有分支与内容。切换分支或合并属于单独决策，不借整理之名进行。

## 未提交内容先保

- 有未提交修改或未跟踪文件的工作树，不使用强制删除。
- 先把内容提交到分支，或完整归档并登记去向，再处理工作树本身。
- 未提交内容不代表功能完成，也不代表已合并或已验收。

## 交付后收尾

- 只有交付物已合并，或确认不再需要时，才移除对应工作树。
- 移除前确认工作区干净，并记录分支与 HEAD。
- 移除工作树不等于删除分支；分支删除另行决定。

## 归档不是合并

- 目录归档、bundle 与元数据快照只用于恢复，不代表代码已进入主线。
- 代码进入主线必须经过 PR 与审查，整理结果不能替代这一步。

## 不让工作树散落

- 同时存在的工作树应有台账（分支、HEAD、用途、去向），任务结束后及时收口。
- 不在 `.claude/worktrees/` 下长期堆放临时副本；临时副本完成后即清理，或登记为保留。
