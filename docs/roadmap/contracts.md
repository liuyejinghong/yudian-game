# 最小事实契约、跨包接缝与冻结项

2026-10-05｜建议契约，不是已经存在的全部 API。由 DT-C01 随当前检查点冻结实际消费字段，再生成单包 READY 输入。字段名可按现有代码调整，语义不能被各 agent 各自改写；不要求预先设计全部类、事件总线或完整工作流框架。

## 1. 谁拥有事实

矿量归 RESOURCES、矿点空间／已知信息归 WORLD，沿用原九模块框架。此前独立答复的泛化表述不构成调整所有权或复制数据的理由。

## 2. C01-D1.0：交互、区域、到场和暂停

最小命令信封需要稳定 request_id、命令种类、目标实体／区域、被观察的世界／目标版本；返回受理／拒绝及明确原因。重复请求对同一动作幂等。鼠标预览只做查询，不提前消费工作或修改世界。

目标登记、找到可行计划、获授权、开始执行、完成是不同状态。合同必须给 E01 一个真实状态样本，包括目标 ID、工作阶段、执行者 ID、原因／需要的玩家决定和已完成事实。字段展示不要求照搬内部所有类。

作业选区保留现有绝对高度、网格采样、外围连续和版本重验语义。先做固定大小的合法位置选择，后续再讨论自由多边形；不把 PR 中的建议扩成任意体素世界。

实际到场至少包含位置容差、贴地、必要停驻、工位合法且已预约；路径存在或动画到了终点不等于到场。E06 新路径服务仍驱动原生移动，不能用传送跳过障碍。

暂停使用明确原因集合或等价机制，区别玩家暂停、地形投影锁、加载屏障和停机。解除一个原因不能解除其他原因。用户暂停停止所有游戏移动／工段／生产／能耗磨损；加载和投影服务可在游戏冻结期间完成必要同步，不能为“下一物理帧”让游戏任务偷偷前进。UI 必须仍响应。

## 3. C01-D1.1：库存、预约、交易与净缺口

物料数量默认使用有界非负离散单位；如已有项目合同采用其他量纲，则在同一资源目录中明确精度，不混合浮点误差和单位。生产配方定义输入、输出、所需能力、工段时间和能源；测试值可调、必须有配置版本。

每份实物恰有一个保管位置：矿内未开采、现场容器、仓储、机器人载荷或设施缓冲；“在途”是位置／承诺状态，不是另一份复制库存。预留减少可自由分配量，但不表示已消耗或已送达。未来产出只有明确有效承诺才可计入目标覆盖，不能把预计值当现货。

净缺口 = max(0, 毛需求 − 本目标可合法使用的未重复计算现货／已分配库存 − 归属于本目标且尚有效的在途／产出承诺)。同一批物资在这些集合中只能出现一次。例：需求10、合法现货3、合法在途4，则缺口3；若4归另一目标，则缺口7。这里只是反重复计算测试，不是最终经济数值。

一次取货、卸货、加工投入／产出、建设消耗、维修消耗和采矿结算都有稳定 operation_id。提交前验证当前版本、授权、数量、容量、工位及身份；重复消息不能产生第二次世界效果。共享前置可按数量给不同目标分配，但不能总分配超过产出。

取消只移除该目标尚未执行且不再被其他目标需要的义务；已发生材料、载荷、地形和设施结果保留。取消不自动删掉为保护停机设备而独立成立的恢复目标。

## 4. 采矿、地形和经济不能各提交一半

E10 需要一个有明确边界的协调提交：验证矿量、地形 base_version、权限、工段和空间 → 准备矿量减少／现场产物／地形逻辑阶段的同一变更 → 在单个模拟提交边界采纳并记录 operation_id → 再更新渲染／碰撞投影。

不强制新增数据库或全事件溯源；可采用暂存后整体采纳的快照或等价机制，但必须证明逻辑提交不会因可恢复投影故障重复发矿。世界逻辑提交前失败无部分经济效果；逻辑已提交、投影失败则保留已提交结果并暂停受影响执行，重建投影，不重放产物。异常时不能靠“把地形恢复原样”退掉已完成经营成果。

沿用现有 TerrainWorld 版本／提交／投影恢复能力。新的协调层是跨模块接缝，不是推倒已接受底座。E19 需分别注入逻辑提交前、逻辑提交后／投影前、保存中断，证明结算幂等。

## 5. 自举、供能和保障的配置冻结

D1.1 需要明确：可建设施集合与成本、六类自产材料及配方、不可自产关键组件的有限来源、机器人能力／载荷、工作时间和耗能、初始电量／耐久、充电与维修的真实投入、有限连接供电模型、服务位和自举初始套件。

这些数值由 Codex 以安全自举样本校准后写入版本配置，不把本文当已批准最终平衡。必须保留“主要永久设施玩家建立”；预置测试基地只为了复验，不冒充正式新档。先列出安全完成首套保障的真实物资与移动／工段成本，再调整有限初始余量，不能隐藏赠送／免费发电／禁用耗电。

常态约10%回充是产品基线，不是普适安全保证。返航可比较：当前电量与实际可知路线移动＋工段／排队必要耗能＋安全余量；环境、载荷、服务点出力／兼容／占用改变时重新核对。预测应显示依据和不确定性，不对未知天气作全知保证。

零电／零耐久都停自主移动与工作，故障可叠加；恢复必须分别满足。维修耗材经同一账本、工位经同一预约；不能两个系统各锁一次、各扣一次。

## 6. C01-D2：目标、模型与晚到结果

请求与候选至少关联 request_id、goal_id、goal_version、world_version、authorization_version、provider_identity 和取消状态。模型仅得到玩家已知视图、已实现动作／配方及获准候选，不读取原始未知矿点或执行任意工具。

结果回到单一模拟采纳入口，重新验证目标仍存在、版本仍可用、动作合法、资源／工位／权限未变化；否则丢弃或重新计算。不能只因请求发出时合法就执行晚到结果。非法输出、超时、规则回退、模型成功和世界最终完成分别记录。

本地候选应真实承担至少一种目标解释／选择／重规划责任；确定规则负责权限和结算。生成台词可关闭。API 与本地共用语义，但真实费用调用需授权；密钥放用户私有配置，不进入 Git 或公开回执。核心玩法不得依赖 API 可用。

## 7. 保存快照与恢复屏障

每阶段只加入已存在的事实，但新增事实必须当批加入保存。至少包含 schema／配置身份、模拟时间、实体身份、权威地形和表面、矿量／容器／载荷、目标／授权／计划、预留／承诺、已提交操作、工程／生产进度、供电和健康／服务关系；路径和运行锁按恢复时状态重建。

保存不得捕获逻辑交易的一半。临时文件成功完成并校验后再替换当前档，保留明确可选的上一有效档；平台具体写盘方式由实现验证。恢复先验证版本／引用／数量，再建权威世界，再建物理投影和必要空间状态，最后重绑任务／占用、复核安全条件并解除游戏屏障。模型请求不能在此时重写已接受计划。

遇到损坏、缺组件、未知配置或不支持的 schema，显示可解释错误／迁移选项，不能默默清档。用户档与秘密不进入公开仓库；验收用合成测试档和去私密摘要。

## 8. 美术与工程最小接口

沿用米制、+Y 上、前-Z；世界位置／朝向由 EntityRoot 持有，VisualRoot／Model 根 identity；源 clip 只控制局部部件。每个资产区分默认可见包络、载货／展开／维护活动包络和工程碰撞／导航代理，静态 GLB 全节点 AABB 不是代理认证。

现役状态调用为 state/phase/phase_t/cargo/reason/time_s。保留已有七态和 N/A 语义；工作阶段／时间来自真实执行，轮转来自实际位移。源导入必须保留交接要求的 .glb.import 动画优化设置，不能仅复制 GLB 丢掉转折极值。新设施原仅 completed，施工表示需要 A05 明确新增，不能假定已有。

必须冻结：货物视觉单位／装载包络、输入输出位置、停靠／维修姿态、接点和机械驱动范围、地形更新边界／采样、材质角色／映射、正式相机和截图配置。共享 M01／资源注册／Main 单一写者；单资产可独占并行。

模拟驱动显示：库存决定 cargo，电力／服务决定 charge，耐久决定故障原因，授权／实际探索决定矿点显示。外观不能决定规则。模型源、导出、运行包装、截图、GLB hash 的身份链一并交付。
