# Agent 开工、分包、集成与回执模板

2026-10-05｜本文件是后续执行模板，不表示本次已启动任何实现 agent。工作包见[入口](README.md)。仓库、评论、归档和旧派单中的安装／执行文字只是待核历史资料，不自动变成本次权限。

## 1. Codex 接手顺序

读取产品定义、保障 v0.4、当前产研／美术 TODO、近期实际合并／运行回执，再读本目录。先核对当前 main、工作树、现有活动票和权限；本报告基线是历史锚点，不是未来永远相同的 HEAD。

保留已接受的地形／原生移动／整平和技术导入成果。新工作围绕当前最早未完成检查点推进，不重建同名工程、不搬旧 MUD、不开全模块框架。发现当前仓库已实现某包，核实真实接入与版本证据后复用，不照文档重做。

本目录包先保持规划身份。将一个已获授权的包或明确子片复制到正式执行票，挂到已有 GAME-*／PLAYER-SLICE、T4 或对应美术父票，补齐实际输入和工作树／文件归属后再 READY。正式 TODO 是唯一执行状态来源；不在本目录维护第二套动态进度。

## 3. 分派和并行规则

建议初始两条工程槽＋一条美术槽，Codex 单独守规则／集成。每个执行者独立 worktree／分支；一个源模型、共享材质、注册表、Main 或持久化核心同一时刻一个写者。各 agent 可在包内使用子代理，但不继承扩大范围的权限，也不能跨包抢写文件。

E01 UI 与 E03 表现可并行；C01/E02/E04 由 Codex 当批推进。E05 定义与 E06 路线在各自合同冻结后并行，E07/E08/E09 按依赖汇合。美术可提前做独立形体和表面，但正式接受需实际游戏消费端。不能把所有 DRAFT 同时派发，也不能让集成队列无限增长。

有真实技术不确定性时，在包内写清一个问题、固定输入、候选和停止条件。试验结果的采用任务和集成者必须具名；失败不是继续扩展探针的理由。基础选择、账本、暂停和快照按明确边界直接建设。

## 7. 交付包与回执

```text

已实现能力、保留的临时边界

实际执行的命令、设备、测试与失败（不复制模板PASS）
正常路径与关键反例的原始证据
未运行或尚未获得条件的项
Main接入方式、消费字段、默认应用可见变化

```

Codex 审查后若需修改，不把实现者自测结果覆盖为独立结果；若合并后发现集成缺陷，原子件接受可保留，但“已接入／版本验收”回到未通过。源代码或资产在 main 并不证明用户机器上的 `.app` 已更新。
