# 联合里程碑：每次都把产研和美术送入同一个可玩版本

2026-10-05｜PROPOSED。命名与授权见[入口](README.md)。本页是验收路线，不是排期；全部新增检查点尚未执行。DT-* 详情分别见[产研 D1](engineering-d1.md)、[产研后续](engineering-d2-d3.md)、[美术](art-work-packages.md)。

## 1. 版本链与不应串行的工作

主链：D1.0 → D1.1 → D1.2（D1）→ D2.0 → D2.1 → D2.2（G1）→ D3.0。P1 是可在 D1.2—D2 期间展开的生产质量切片，R1 是实际发行候选关口，不把 P1 混成新玩法里程碑。

这不是所有工作严格串行：DT-E14 本地候选试验可从 D1.1 的受限世界／动作合同起步，随后必须接 D1.2 的真实任务；资源定义、路径子件、UI 和资源素材可以在各自输入冻结后并行。不能要求先完成九个模块再开始试玩，也不能因本地模型未选定停做账本和建设。每项试验必须有接入包，不允许永久停在独立探针。

## 2. D1.0：可操作场地（历史 M1）

**玩家结果：**从普通默认入口进入一个有限 3D 场地，操作镜头，选中机器人／地面，预览合法作业范围，下达或取消整平；看到筑垒真实到场、作业、地表提交和结果；保存退出后恢复本批已存在的世界与单任务事实。

**入口：**保留现有 Main 地形权威／碰撞同步、原生订单和固定整平证据；DT-C01 冻结 D1.0 合同及相机候选。工程验证场景继续可显式进入，但不是普通启动默认页面。

**交付顺序：**
1. Codex 从固定整平中抽出本批实际需要的区域和任务参数（DT-E02），不重做 TerrainWorld。
2. DT-E01 交互与 DT-E03 模型适配并行；DT-A01 在带 UI 的实际视口校准，DT-A03 提供选择／合法性／成果表达。
3. DT-E04 把单任务、实体和地形写入版本化磁盘快照；待物理投影验证完成再解除加载屏障。
4. DT-C02 接回 Main、更新默认应用，进行现场与存档往返验收。

**退出：**普通入口完成下单→到场→真实整平→取消／完成→保存重载；无效选区无副作用；已改造结果不因取消消失；关闭日志仍知道谁在做什么。低保真模型只是视觉子节点，不能自行移动根节点或修改地形。

**不包括：**资源采集、通用建设、保障闭环、本地 AI 验收。此版允许标“可操作场地”，不能标“经营首玩完成”。

## 3. D1.1：从着陆器和有限物资开始建设（历史 M2a）

**玩家结果：**选择一项有用设施的位置与建设目标，机器人搬运实际物资、整平、施工，落成后真正增加可用能力。供电、机器人耗电／磨损和基础回充／维修已经进入同一规则链。

**入口：**D1.0 默认入口可用；DT-E05 账本／物料提交、DT-E06 有限路线与工位合同冻结；新档套件和自举核算由 Codex 负责。测试预置基地与正式新档必须有不同场景 ID 和界面标签。

**最小内容：**新档有着陆器、有限套件／关键组件和有界初始机器人能源；主要永久设施由玩家建。首期从当前设施目录选择太阳能、充电、仓储／加工／维修的必要自举子集，不预先把大半基地放好。可调测试数值不是最终平衡。

**交付顺序：**E05、E06 与 A04 的载荷／类别子片并行 → E07 实际取送 → E08 有材料建设及明确落成效果 → E09 供电和基础保障 → E12 的本阶段快照扩展 → C02 打包。A05 负责建设阶段，A06 先交充电／维修联合姿态，E03 负责状态接入。

**自举必须算清：**按真实移动距离、搬运次数、施工／保障工段估算首条合法链的能耗与物料；初始余量覆盖完成首套可用保障的安全路径。缺关键不可自产组件时诚实阻塞。不得隐形发电、免费维修、瞬移送货、关闭耗电以掩盖自举死锁。

**退出：**至少一项玩家建造设施真实影响供电、储存或加工能力；材料、货物位置和电量／耐久可核对；正常回充与维修可在安全测试条件下自动发生。保存重载不重复落成、扣料或恢复电量。此时缺料自动展开可以仍仅覆盖已明确支持的范围，不冒称 G1。

## 4. D1.2：可持续经营首玩（历史 M2b；D1 出口）

**玩家结果：**缺料时，机器人在授权内采集铁铜、运输、加工铁料／铜料、制造结构件／线缆、运抵并施工；保障打断后可接续。完成首目标后，玩家能选择至少两个有不同后果的发展方向，而不是只能重复唯一按钮。

**入口：**D1.1 的真实成本和保障可用。E10 矿点／加工与 E11 有界目标展开使用同一账本；不可自产关键组件来自明确有限库存，不编配方。E12 覆盖所有新增事实。

**联合交付：**E10/E11/E12/E13 + A04 六类资源完整表示、A05 建设／运行、A07 状态可读性；所有内容进入普通应用。受支持目标默认取已有太阳能和仓储或加工中的第二项，Codex 以产品和既有能力定案，不新增设施种类凑数量。

**决策观察：**玩家可比较扩大供电与扩大加工／储存、靠近资源与靠近保障、先建设与保护维修物资。成本、通路和能力差异真实生效；机器人补操作前置而不替玩家决定下一个发展方向。

**退出：**从正式自举配置走到至少两次发展；再用独立预置测试存档快速检查净缺口、无来源、取消和保障。玩家不需逐配方下单；无隐藏赠送；地形、库存、在途、资源预留、任务、设施、电量／耐久保存一致；真人能解释等待与下一项决策。原型规划器或本地能力未验必须在版本范围中注明，D1 通过不等于 G1。

## 5. D2.0：多目标、已知变化与有限勘探

**玩家结果：**两个目标竞争同一机器人、服务位或材料时，优先级和保护条件有效；取消一个目标不会抹掉另一目标的共享前置；矿点或路线改变后，系统处理剩余工作。望山在获准范围实际勘探，发现后再把情报交给目标系统。

**工作包：**E15 多目标／共享承诺／取消；E16 已知情报与勘探；E12 持续扩展；A07 原因和请求反馈、A08 地标／矿点发现表示。E14 的本地试验此时应已用真实受限状态验证过一次。

**退出：**正常完成、合法替代、需要授权、需要条件四类结果可区分；取消、低电、路线变更和发现信息都能触发有界重验，不能无限重规划。未知矿点不出现在规划输入、普通地图标记或语言解释中。压力不依赖故意把机器人做笨。

## 6. D2.1：本地委托、动态保障和停机恢复

**玩家结果：**断网后在已安装本地组件的条件下，通过鼠标或有限中文提出同类目标，本地候选真实参与解释／方案选择／重规划，规则验证后执行。零电与零耐久分别处理，有能力的机器人完成已批准的救援／送回维修链；晚到或非法模型结果不能越权。

**工作包：**E17 动态返航／停机／救援；E18 本地提供者／中文等价入口；E19 恢复与故障注入；A06 救援子片、A07 状态；C02 同批集成。

**前置门槛：**具体零电恢复方式、救援者／载荷范围和风险授权必须在相关子票冻结；未定项仅阻塞该子片，不能阻塞 UI、资源和安全回充。零耐久需送回维修这一产品要求不是待选项。

**退出：**同一存档在本地模式执行真实目标，保存已接受计划而不重发模型改写历史；模型失效有可见安全回退；停机、拖运、维修、补能和原任务接续可追溯。API 适配可用模拟提供者验证协议与故障，真实付费调用须单独授权；模拟通过不能写成真实 API 已通过。

## 7. D2.2：G1 联合验收，不再按单系统加总

**入口：**上述能力进入同一普通应用。E20 负责联合性能、干净安装和设备验证；当前低保真正式接入的小样已完成，不要求全资产高保真。

**退出：**逐项检查[验收矩阵](acceptance.md)的 A01—A24、B01—B08。实际测试设备、模型版本、启动配置、场景、包 hash 与来源 commit 齐全；真实应用内同时改地形、执行任务、重规划和保存。帧时间、模拟速度、峰值内存、目标响应与存档时间共同记录。功能、真人理解／意愿、所有者视觉分别签字。

没有较低配置或真实 API 授权就对应 NOT_RUN；可以交付边界明确的试验版，但不得宣布完整 G1 全过。完整游戏画面未验时也不能拿独立预览代签。

## 8. P1：可重复的制作切片（与 D1.2—D2 并行）

A09 只在正常视距、低保真轮廓、尺寸／接口与相关玩法稳定，并获得所有者开启高保真授权后开始。默认候选为一个机器人、两类代表设施、一段真实整平／开挖地表及其 UI／声音组合；具体对象按当前稳定性选，不直接铺开十四条。

第一件建立源→导出→导入→状态→游戏画面→性能流程；第二个同类内容复验可复制性并记录实际制作、审查与返修投入。高模／UV／烘焙／LOD 按可见用途选择，不机械要求每件齐套。失败按模型、引擎显示、镜头、状态接入、规则分别定位，未受影响成果保留。

P1 通过仅允许按实际产能扩展相同流水线，不代替 D2 的经济／AI 验收。D2 的功能建设也不因 P1 尚未完成而停止。

## 9. D3.0 与 R1：有边界地扩展和真正交付

D3.0：E21 + A08/A10。在已支持有限世界中增加至少一个需要不同运输／保障取舍的区域或矿源组合；先验证两处地点的布局与经营差异，再决定是否需要更大地图技术。扩张前后保存一致、未知信息不泄露、旧基地继续可运转。不自动加入整星球流式、多层地下、战斗或新资源。

R1：E22 + A10。先按 D1/D2/P1/D3 的实测产能冻结实际发行范围，再做完整开始／继续、引导与可读设置、存档版本迁移、损坏回退、原生安装／首次启动、内容来源与许可、模型组件安装／移除、发布说明与回归矩阵。macOS 与后续 Windows 各自验收，不从一个平台外推。商店上传、公证签名、购买工具、账号与付费 API 均需要相应授权，不由规划文档代签。
