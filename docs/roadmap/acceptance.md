2026-10-05｜测试规格提案，新增用例全部 NOT_RUN。不是执行报告，不覆盖历史限定接受。来源：[产品§14—15](../product/product-definition.md)、[保障 B01—B08](../product/energy-return-and-rescue.md)。本页只建立需求→工作包→版本证据的关系，不更改原编号或降低 G1 门槛。

## 1. 每个版本必须同时验三件事

规则正确：世界、资源、执行、保障、权限和保存同源。玩家理解：关闭日志／生成台词仍知道目标、执行者、等待原因和自己要决定什么。交付存在：从本批普通默认应用实际操作，不用测试窗口或独立预览代替。

D1.0／D1.1 是内部检查点，不因部分用例通过便称 D1 或 G1。D1.2 可以验经营首玩；完整 G1 的本地能力、变化、恢复和联合性能仍由 D2.2 逐项检查。缺设备／真实 API 授权保留 NOT_RUN，并在版本名称和范围中说明。

## 5. 可玩性与视觉验收

真人观察记录初始说明、是否需帮助、玩家自己的目标／位置／优先级选择、对等待原因的理解、看见结果后的调整、是否自发提出下一发展目标、停止原因。允许随时停止，不设必须玩满时长。不得用 agent 数量、点击数、任务完成速度或日志 PASS 代替持续经营意愿。

视觉复看固定模型／材质／相机／灯光／UI／画质和对应状态源。优先正常工作视距，再总览／近景；部分大设施近景裁切不能被当缺件。截图只证明该帧可见内容，不证明连续动画、UV质量、碰撞、导航或性能。所有者视觉反馈和产研技术结果独立。

若体验不成立，先区分目标价值、空间／物流代价、等待信息、表现反馈或规则缺陷，再改最小范围。保留已有效的地形、移动、交易、源模型、导入和存档底座。
