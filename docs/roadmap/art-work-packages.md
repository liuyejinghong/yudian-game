# 美术路线：从当前低保真到游戏内可读、可重复生产

2026-10-05｜PROPOSED。先看[当前资产审查](../art/production/review/2026-10-05-independent-review.md)，再使用本页；“可继续集成验证”不是所有者 ACCEPTED。游戏规则、导航、碰撞、库存、供能、保存和联合性能由产研验收，美术只交可编辑资产与自己的技术／视觉证据。

共用[合同](contracts.md)与[Agent 交接](agent-entry.md)。当前规范是米制、+Y、前-Z、外部实体根持有位置，现有六键状态与共享材质角色优先沿用。每个包 READY 前冻结实际源／导出／manifest／包装目录、相机样本、目标状态和本批游戏消费端；不要求所有类别都做、不重做整个低保真库。

## DT-A01｜实际工作相机、尺度与显示条件

**负责人／前置：**美术给候选，Codex 持有相机／灯光／UI 配置，所有者看样；D1.0，C01/E01 初始视口和现役 manifest。可与 E01 的 UI 骨架并行，最终以同一个游戏 viewport 收口。

**归属／输出：**美术只写专属参考记录和独立对照场景；主场景镜头、灯光、渲染器与共享材质由 Codex 合入。记录窗口实际像素、UI 缩放／占用、投影／角度、正常作业／总览／近景三个档、曝光／光照、模型和材质版本。

**制作步骤：**在同一小基地放三机器人、代表设施、整平／开挖点与 UI 占位；先在现有 reference normal 旁给一个适合操作的候选，不因机器人显小直接放大全部模型。比较遮挡、可点击性、尺度和地表成果；再看缩远和近景。

**验收／返修：**正常档能选择和区分对象；总览仍有必要标识；较大设施不因固定近景裁切被误判为缺件。确定问题属于模型、相机还是 UI 后只修对应部分。所有者未看样不写视觉已通过。

**联调：**E01/E03/C02 使用候选条件出实际游戏截图，不拿独立预览称默认应用画面。

## DT-A04｜六类资源与容器／载荷表示

**时机／负责人：**D1.1 子片、D1.2 完整；美术；前置 E05 的资源定义、单件／一批视觉语义、货物外包络和 A01 视距。

**归属／交付：**独立资源源文件、GLB／材质／必要图标、manifest 和正常／近景对照。只做铁矿、铜矿、铁料、铜料、结构件、线缆；通用容器可复用 P01-CRATE。不可自产关键组件按产品和本批配置使用有限套件标识，不随意增加自产配方或第七条资源工业链。

**步骤：**用形体区别原矿／加工料，结构件有模块轮廓、线缆用卷盘等可辨候选；色相只辅助，不靠微小文字。冻结机器人载荷、仓储格和出料位置的包络；六种不等于六套昂贵独立材质或所有数量各建模型。

**验收：**同种资源在矿点／现场货物／机器人／仓储／设施输出表示一致；实际像素尺寸下至少类别可辨；载荷不明显穿车体或工位；精确数量由账本 UI 给出，不能靠数箱子推算库存；空载／混合或多批显示规则由产研冻结。

**联调：**E07/E10/E13 实际取送加工消费资源 ID；新材料出现在普通流程中才记接入。交付范围不足时明确哪些只是候选，不称六类全完成。

**时机／负责人：**D1.1—D1.2；美术制作，Codex E08/E10 接线；前置设施占地／作业包络、工段和输入输出位置。

**联调：**E08 工程／E10 生产给进度，E03 适配；C02 复看不同朝向、邻近设备和接入后的选择／碰撞代理，不以空场景 clip 截图结项。

## DT-A06｜充电、维修与救援的成对接口

**时机／负责人：**服务子片 D1.1、救援子片 D2.1；美术，Codex E09/E17 规则和实机。两子片分开冻结，未定救援不阻塞充电／维修。

**前置：**实际兼容对象、停靠姿态、Socket_Dock／Socket_Bay 位置、静态／活动包络、接触机构驱动与状态来源。当前充电预留约.17m间隙是交接边界，不擅挪 socket 假装已经接上。

**归属／输出：**F04/F05、被服务机器人、回收杆相关的明确局部源／包装；单体变更一个写者。成对正常和近景、动作端点／包络、导出设置、接口版本记录。

**步骤：**先做真实车辆到位的充电接触／维修工具区；收到救援方式和能力批准后，再制作连接／牵引或已选方式的双体姿态与脱开状态。单杆图不能代替两车转弯、坡地和工位关系。

**验收：**静态停靠与允许动作端点无明显穿插；不同机器人兼容表明确，不默认所有型号互救；维修只表示实际进度，不通过动画赠电；被拖动不显示已经恢复自主。连续动画、物理、路线、救援能耗和保存由 Codex 在实际游戏中另验。

**范围：**一机器人＋两种代表设施＋一段真实整平／开挖地表和对应 UI／声音组合。先选最稳定的对象，不因 U01 是历史首样就忽略其待返修，也不评价未列入当前审阅入口的历史高保真实验。

**制作：**概念与功能说明→灰模锁轮廓／包络→按用途细化→源文件和导出→共享材质接入→状态回归→同条件游戏画面。仅当细节在目标视距有价值时做高模、UV、贴图／烘焙；简单着色设备可以保持轻量，不机械要求所有步骤。

## DT-A10｜按用途扩展、规模优化与发行素材收口

**时机／负责人：**D3/R1；美术，Codex E20—E22 联调；前置 P1 生产结果和已批准内容清单。

**范围／输出：**按真实版本需求扩展既有设施／环境／图标／声音，记录各资产出处、许可、源／导出版本、状态覆盖、实际实例数量、必要 LOD／纹理质量档。只为已存在的玩家行为补素材，不开战斗、角色、生态等无用途类别。

## 2. 每次美术回执最少包含

资产 ID／revision；输入合同和 base SHA；源、GLB、材质、包装与必要导入设置；当前字节 hash；尺寸／轴向／根变换／静态与活动包络／接口；支持状态与 N/A；本次变化、正常镜头证据、补看近景原因；已核验和 NOT_RUN；对应产研包、集成者与目标检查点。原图保留相对目录，接入者可以从记录定位到确切字节。

美术不自验收游戏；产研也不因技术导入成功就代签所有者审美。遇到整场问题先定位责任层，再退回最小受影响范围。
