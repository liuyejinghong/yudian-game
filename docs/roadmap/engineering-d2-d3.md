# 产研后续：本地委托、G1、扩张与发行工作包

2026-10-05｜PROPOSED。与[产研 D1](engineering-d1.md)共用 DT-C01 合同和 DT-C02 同批集成责任。所有路径先按当前仓库核对，再冻结独占写入范围；不预建空模块。产品承诺和未批准细节以[入口](README.md)所列来源为准。

## DT-E14｜提前检验本地候选，但不制造旁路演示

**时机／负责：**D1.1 起准备，D1.2 真实任务中复验；GAME-GOALS／T4；Codex 试验设计和裁决，GLM 数据适配／评估工具。不是等 D2 才首次考虑本地能力。

**前置／输入：**C01 的目标、只读世界、合法动作和授权 schema；E05 的归属语义；初期可用合同级样本，E11/E10 可用后必须消费实际快照并执行方案。规则参考＋至多两种与实际机器相符的本地候选即可，不无边界评测所有模型。

**归属：**拟 `Goals/Providers/` 的独立适配和 `tools/goal-eval/`；不修改权威账本、地形或安全约束。不擅装软件、购买服务、上传世界快照、提交权重或秘密。

**试验：**相同受支持目标覆盖库存足／缺、在途归属不同、缺设施、未知矿点、保护资源、无来源、取消、变更和非法输出；留出未在提示词中逐案教答案的组合。模型必须实际影响目标解释、候选选择或重规划之一，明确其责任；“规则给答案＋模型说好听话”不算。

**输出：**实际提供者／组件版本和配置、机器与内存、请求输入、候选结果、合法性拒绝原因、世界执行结果、延迟分布和峰值内存；分母、失败、超时、回退均保留。数值性能门槛由实际设备目标冻结，不编造成功率或最低配置。

**采用出口：**成功候选由 E18 接普通目标入口；不合适则局部替换适配或缩小受支持表达范围并明确影响，不削掉本地核心承诺；规则、资源、建设和 UI 继续。独立 harness 不能结清 T4 或 G1。

## DT-E15｜多目标竞争、共享前置、取消和有界重规划

**时机／负责：**D2.0；GAME-GOALS/ROBOTS/RESOURCES/SUPPORT；Codex 核心，GLM 纯调度／查询子件。前置 E05—E12 已接通。

**归属：**拟 Goals 的承诺／重规划核心、TaskExecution 调度接缝；GLM 只写冻结的纯函数和展示适配，Main／事务由 Codex。

**步骤：**目标持有稳定身份与授权版本；共享产出可按数量分配、不可重复承诺；执行者和工位使用已有统一预约。优先级调整只影响未提交／可安全交接工作，不撤销物理成果。取消释放未发生义务、保留真实货物／已完成改造和其他目标仍需的前置。

**公平性默认：**同优先级 FIFO，等待可老化；在有可用能力且负载受限时避免永久饥饿。安全恢复与普通扩张的优先级、准入及过期语义由合同明确；不能用无限新增高优先级任务掩盖饥饿。避免同时持有互相等待的无进展工位；冲突可释放后有界重试。

**验收：**两目标争同一份材料／同一机器人／充电位；一个取消、一个继续；运输途中改优先级；工地受阻、矿点不可用和低电引起剩余计划重验；超范围替代等待批准。不存在负库存、双占、重复开采、无限 TODO、永远重试或传送解锁。

**可见交付：**目标卡说明谁先做、谁等待、取消影响；E12/E19 保存共享关系；A07 显示实际原因；C02 在普通应用中执行两目标测试，不只跑调度单测。

## DT-E16｜有限勘探与已知情报边界

**时机／负责：**D2.0；GAME-WORLD/GOALS；Codex 情报权限，GLM 勘探执行／显示。前置 E06/E11；E15 的目标变更合同用于发现后续计划。

**归属：**拟 WorldKnowledge 的已知视图／调查动作，PlayerUI 的指定显示；原始矿量仍由 Resources 持有。

**输入／步骤：**有限地图中已存在但玩家未知的矿点，允许调查区域、望山能力／路线、实际工作条件；只向规划器提供已知视图与获准调查动作。真实到达并完成勘探工段后发布发现，重验剩余计划；不从探头动画反推发现。

**验收：**未发现矿种／存量不泄漏到普通地图、标记、模型解释或候选排序；调试视图不能成为模型输入。区外调查拒绝；取消／低电保留合法已发现成果；同一点重复发现幂等；无发现可以诚实结束而非编造矿源；保存恢复已知状态。

**素材／可见交付：**A08 自然定位物、迹象与已发现标记，A07 扫描状态；E13 对应反馈。C02 在同一小地图验“未知→获准调查→真实发现→建设计划改变”，不等 D3 才处理探索。

## DT-E17｜动态返航、零电／零耐久与有成本救援

**时机／负责：**D2.1；GAME-SUPPORT/ROBOTS；Codex 规则和集成，GLM 冻结后的预测／执行子件。前置 E09/E15/E06；未定救援能力只阻塞对应子片。

**批准门槛：**零耐久必须由其他机器人送回维修已确认；零电到底拖回、现场补能或其他已批准方式，以及哪型可救哪型、载荷和附件范围，必须有所有者或既有明确决定。不得用 P01 回收杆外观自动批准拖救机制。

**子片 E17a（可先做）：**用实际可知路线、载荷、坡度／环境电耗、充电站出力／兼容／排队预测返程成本和安全余量。常态约10%不是最迟返航硬门槛；工段／路线／天气／服务点改变时重评，不每帧调用模型。已知预算不足不能作为普通安全任务继续。

**子片 E17b（相关能力冻结后）：**停机登记→核救援者去程／负载返程预算→预约能力与目的工位→到场连接／装载→真实运回→维修／补能→检查所有恢复条件→恢复适合任务。原货物和其他目标的承诺不丢失。

**验收：**高电零耐久、零电高耐久、两者为零三档分别处理；无已知安全救援路线明确等待，不派第二台继续耗尽；回充不修耐久、维修不赠电；拖运位置改变不等于恢复自主工作；救援取消不删除停机身份或货物。环境增耗只按定义影响，不额外无来源再扣一遍产量。

**联调：**A06 双体包络／接点／维修位置，A07 原因表达；E19 在停机／拖运／维修中保存。C02 同时验安全可持续档和明确授权的风险档，不强迫新手首夜遇灾。

## DT-E18｜本地提供者正式接入与有限中文等价入口

**时机／负责：**D2.1；GAME-GOALS/UX；Codex，GLM 可做冻结 provider／中文解析 UI 子件。前置 E14 候选结果、E11/E15 权限与版本，E16 已知信息过滤。

**归属：**Goals/Providers、指定输入面板；权威计划采纳和世界动作仍由 Codex。

**步骤：**鼠标目标与有限中文先变成同一目标卡，位置／范围／预算／保护条件可核对后提交；模型不直接操作游戏对象。候选带 request_id、goal_version、world_version、authorization_version；采纳前重验。超时／非法／晚到／取消后的结果丢弃或按明确规则重验，不能恢复已取消义务。

**本地边界：**记录安装、模型／运行组件／配置身份、可用状态、取消和资源释放；已装好组件后断网，新建／读取／委托／保存完整可用。缺组件显示安装／回退状态，不悄悄改用付费云端。模型权重、用户输入、API 密钥不得提交仓库或未经同意上传。

**API 边界：**与本地共用目标／授权／存档语义；模拟 provider 可测超时和非法返回，但真实 API 调用须单独授权且费用边界可见，未跑记 NOT_RUN。

**验收：**同一目标两种入口结果语义一致；本地真实参与决策且最终世界结果有效；非法材料／配方／未知情报不进计划；已有安全任务不因推理失败卡死 UI；已接受计划读档不重新询问模型覆盖历史。关闭生成台词不影响理解。

**联调：**C02 在默认应用实测离线和切换，E19 注入故障；规则回退单列，不冒充模型成功。

## DT-E19｜跨系统恢复、故障注入与幂等结算

**时机／负责：**D2.1；GAME-SAVE/DELIVERY；Codex，GLM 故障工具和确定 codec。前置 E12；E15/E17/E18 的新增事实随子片加入，不要求等其全部完工才测。

**归属：**Persistence 恢复、专用 QA fault harness；不将测试注入开关默认为玩家作弊按钮。

**注入点：**采矿逻辑提交后／投影前、取货后／卸货前、加工已扣输入但未产出、建设落成登记边界、服务队列、拖运连接、维修进度、模型发出后／采纳前、写档临时文件阶段。每个点记录前后权威摘要。

**验收：**重开后不返矿、不重产、不重扣、不重复建造；逻辑已提交而投影失败时恢复投影，不重发经济事件；未知／旧 schema 有明示迁移或拒绝；损坏主档能按明确策略选择上一有效档且不覆盖证据；模型晚到不能改变恢复后的世界版本；无离线收益。

**可见交付：**普通应用解释恢复／缺条件／错误，不突然变新档。原运行期锁与路径重新建立，任务／货物／授权关系一致。C02 用实际跨进程测试，纯 JSON 往返不足结项。

## DT-E20｜G1 联合负载、较低配置与原生交付

**时机／负责：**D2.2；GAME-DELIVERY／PERF／ENV；Codex 实机，GLM 采集／复算工具。前置 D2 已有可运行集成版；性能工具可提前准备，验收必须实际联合。

**归属：**现有性能／生命周期工具的限定扩展、导出和运行记录；不丢弃旧回归，不更换渲染方案来绕过未测事实。

**场景：**正常规模＋经授权的较高负载：真实地形改造／碰撞与路径更新、多机器人生产和保障、本地规划／解释、自动保存同场。记录应用包／commit、资源与模型身份、设备／系统／引擎、分辨率／焦点／渲染器／质量档和模拟速度。

**验收：**保留启动尖刺、失败、最慢帧和前后台差异；报告帧时间分布、模拟推进、峰值内存、计划延迟、保存耗时。不可静默降低模拟速度、删地形／耐久规则、以超分或独立空场景 FPS 冒充联合达标。预算在目标设备上冻结后判断；未取得弱配置标 NOT_RUN。

**交付：**干净导入构建、默认包、移动路径／首次启动／无 SDK 环境等现有 ENV 留项独立证据；macOS 成绩不代签 Windows。联合画面由所有者看，功能由产研测，建模组不代跑游戏验收。

## DT-E21｜有差异的有限区域扩张

**时机／负责：**D3.0；GAME-WORLD/BUILD/GOALS；Codex 设计／规则，GLM 内容数据／独占模块；前置 D2 核心成立，A08/A10 生产输入可用。

**归属：**有限区域／目标配置、允许的新内容目录；跨区事实和保存由 Codex，不默认搭整星球流式系统。

**步骤：**在受支持世界中增加一处与起始区不同的矿源／距离／通路／保障组合；沿用现有资源与设施，让“靠近资源建配套”与“依托主基地运输”形成真实差异。先做两个可比较地点，再按试玩决定扩大地图或内容。

**验收：**旧基地继续运转；新区域授权、探索、物流、供能、保障和存档一致；无全知；两个发展方案不能只是换皮同数值。更大区域如需要新地形边界／跨区提交，单独冻结小片并回归旧区域，不顺便推翻 TerrainWorld。

**联调：**A08 地标提供定位而非虚构新玩法地点；A10 只扩已证明可重复的内容。C02 交新区域可操作包，所有者判断持续经营选择是否增加。

**时机／负责：**R1，部分工具可从 D2 开始；Codex 主控，GLM 专属 UI／工具，美术 A10。前置产品范围经所有者确认、P1 可重复生产证据和相应玩法版本；不因文档列出而启动商业发行。

**输入／步骤：**用实际制作／审查／返修产能决定本次内容清单，不凭便宜 token 扩量；完善新建／继续、分段目标引导、可跳过帮助、输入设置、音量／画质／UI 可读性、模型组件管理、存档版本迁移／回退；保留工程入口但与玩家界面分离。

## 工作量与分包规则

E14/E17/E19/E20 含真实不确定性，应按明确子片、输入与停止条件推进；失败只收窄对应候选结论。E01—E13 的常规能力直接渐进建设，不每项另开一次性探针。一个包超过单一写入边界或无法在当批集成时，按本文已列步骤拆有共同集成票的子包；不把“拆包”变成集成无人负责。
