## 基线和效力

工程／素材审查基线为 `16e573b01c0f7700e44224fd0fafb6e1246ea930`。本 PR 从 `f3ca6f7310a324fbd5b0b8ebd9dd7f0fb664adad` 建立；该提交相对审查基线增加直链交接文档并更新 AGENTS 文本，没有新增工程或模型实现。用户当时持有的应用仍来源于 `3e64e532a3474b2329e52575756c1a79bdac47db`。后续包启动必须重新核对实际 HEAD，不把本页基线当永久最新。

效力顺序：所有者已确认的[产品定义](../product/product-definition.md)、[返航与救援 v0.4](../product/energy-return-and-rescue.md)、[世界与机群补充](../product/world-and-fleet-systems.md)优先；本目录细化实施顺序和建议默认值；单包合同只冻结其实际消费范围。发现冲突必须记录，不默默修改产品。

明确保留：单人 3D 火星基地、macOS Apple Silicon 优先、Godot .NET/C# 当前底座、鼠标目标主入口与有限中文等价入口、真实地表改造、电量和耐久分离、约 10% 常态回充但动态安全预算可更早、零电停机、零耐久由其他机器人送回维修、核心委托本地可用、初期建设成长而非强制首夜受损。不得添加付费 API 必选、无限全自动扩张、战斗、人物、水冰资源、隐藏赠送或永久删档。

## 下一批建议

先由 Codex 做 DT-C01 的 D1.0 子片：冻结本批命令、只读状态、实体身份、选区与暂停／保存边界，并接出真实消费端。随后两个工程槽分别做 DT-E01 玩家操作、DT-E03 视觉适配；Codex 同时推进 DT-E02 参数化整平、DT-E04 最小保存；美术槽推进 DT-A01 镜头／尺度和 DT-A03 场地／操作标记，DT-A02 的 U01 局部返修可独立串行。DT-C02 负责本批合并后的普通入口、应用和验收。

E01/E03 可以在合同样本上独立开发，但结项必须在本批真实场景中消费，不能仅交 mock。U01 尚未被本批使用时，其返修只记制作完成，不能冒称已接入。

初始并行上限建议为两条工程外包槽、一条美术槽，Codex 另负责关键规则与集成。这是限制在制工作的假设，不是已测产能；不虚构日期、百分比、人日或费用。范围以可见结果收口，不因 token 便宜同时打开全部任务。

## 批准和状态

本目录 DT-* 是稳定规划包 ID，不是已创建的 GitHub Issue，也不自带 READY。Codex 可据现有授权将一个包或已定义子片复制到正式任务票，补齐不可推断的输入、独占路径、实际执行者与集成者后才标 READY。高保真启动、未定救援能力和实际发行另过对应门槛。

任何批次都分别记录：已验证、已实现／制作、已接入、已在版本中验收。真人可玩性与所有者视觉意见独立记录。局部失败只撤回受影响结论，不重写有效地形／运动／资源底座。
