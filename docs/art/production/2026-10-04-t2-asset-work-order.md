## 1. 现在实际有什么，需要什么

当前场景在 Main.cs 程序化创建六类设施、三类机器人和地面。机器人沿固定航点插值；设施根节点旋转和柱体悬浮都是 benchmark 占位动画。没有 PackedScene/GLB 资产目录、AnimationPlayer 状态桥、碰撞/导航或可导入资产注册表。

因此当前最有价值的不是巨大基地海报，也不是先做几十个最终资产，而是：

**一个清楚的样件接口 + 地形试验样件 + 一台驮运 + 太阳能与加工两座设施。**

保留 T2 灰模基准为 `gray-r1`，新资源在独立 `art-sample-r1` 场景中测试。两者各有 fixture、材质配置和 hash，不偷偷把新的素材成绩与旧约 120 FPS 比较成同一基准。

## 2. 视觉方向，不重新投票

沿用 Surviving Mars: Relaunched 与 Anno 2205 的专业、明亮、模块化近未来工业气质；原创设计，不复制游戏模型/贴图/商标。RTS 斜俯视，正常白昼优先；浅色功能外壳、深色支撑结构、克制标识，适度尘土，不军事化、不回到32px像素，也不靠过暗/雾/景深隐藏轮廓。

优先级：对象易认 → 工作可理解 → 地表与建成前后变化 → 材质和气氛。所有源图、模型、贴图、展示和导入证据逐项归档；不将计划和版本路线画进美术稿。

## 3. ART-I00：先由主控核定最小接入约定

这是技术与美术的共同前置，不要求先实现完整游戏。

### 当前事实与拟议修正

- 当前 robot root 每帧被设置到 `TerrainHeight + 0.45`，会导致不同尺寸模型落地不一致。**不要用缩放或移动每个资产去迁就这个硬编码**。
- 当前六类设施的占位动画包含根节点整体旋转。游戏展示应固定基座，只驱动工作子件；基准运动要留在基准场景，不成为资产默认。
- 当前机器人不随航向转身。视觉接线应使用路径切线方向，独立于具体模型；不能让艺术文件定义移动或导航规则。

### 建议约定（主控实机导入后固定）

- 工程单位按米；Godot 端 Y-up；机器人视觉前方在导入后统一为 -Z。Blender 源为 Z-up，可用正 Y 作为作者前向；**以实际 GLB 导入校准物和轴向验证为准**，不要求手工再加一层重复90°补偿。
- `EntityRoot` 定位于接触地面位置，由技术线管理稳定身份/位姿/选择/健康。
- `VisualRoot` 是独立可替换子节点。艺术只控制其骨骼和活动部件，不改 EntityRoot 的模拟值。
- 连接点建议：`Socket_Cargo`、`Socket_TowFront`、`Socket_TowRear`、`Socket_Charge`。没有实现的救援方式只提供可见设计与预留，不声称已存在玩法。
- 动作名称建议：`idle`、`move`、`work`、`charge`、`disabled`、`towed`、`maintenance`；不适用的动作在清单标 N/A，不造无意义动画凑数。所有循环关闭root motion；建造动作是可定位阶段，不是动画完成即发资产。
- 工程中可使用 `.tscn` 作为应用包装层，源模型保持独立。碰撞与导航代理由主控激活/验证，艺术不将高模自动转成昂贵运行碰撞。
- 库存、能量、耐久、任务和地形版本均不属于美术文件的权威字段。

建议目录（目前尚不存在，不能假装已经是工程接口）：

```
art/source/{units,facilities,terrain}/       # .blend 原始制作
art/reference/                            # 经确认的原始设计与来源
prototype/assets/{units,facilities,terrain,materials}/  # .glb 与贴图
prototype/scenes/asset_preview/            # 独立预览与比较场景
art/manifests/                            # 素材版本、占地、连接点、预算、许可
```

是否使用 Git LFS 由主控在首次大文件前明确；不把大型资产/权重、个人绝对路径或凭证塞入 Git。此处不添加开源许可证或购买任何资源。

## 5. T3 的地形接缝需要特别小心

当前 TerrainHeight 使用连续 Gaussian，但显示面是有限细分三角网。二者使用同一函数不代表任意点采样与三角插值严格一致。当前没有碰撞/导航，不能把“对象按高度摆放”当作三者一致性已经通过。

主控应冻结地形区域ID、边界、阶段和版本；A线使用导出的边界样本做样件。不同阶段边界要保持连续，不能导入一个漂亮新坡把外围高度接缝留给程序猜。

两候选方案共用相同地形目标与镜头；阶段网格和高度场各自的权威定义由T3确定。模型、贴花和履带痕迹不反向产矿或降低耐久。几何切换、碰撞更新和导航可用之间必须有明确安全状态。

## 6. 每份资产的交付格式

每个资产独立目录，提交：
1. 可编辑源文件（例如 .blend）与用于导入的 .glb；贴图按实际使用提供。
2. asset.json：稳定资产ID、revision、单位、导入后包围盒、原点/前向、连接点、动作、材质数量、三角面、纹理尺寸/色彩空间、文件hash与来源许可。
3. 正常白昼的指挥距离截图；一个近景细节图；不同状态同镜头对照。没有引擎证据的图必须标“设计/离线渲染”，不能标实机。
4. 两级可用细节方案或明确的简化说明。低档能减少装饰，不能删掉土坡改变、停机和货物等关键状态。
5. 导入/播放/载荷/连接点/贴地/阴影/颜色与测量记录；不会做或尚未运行就标NOT_RUN。

本批先记录成本，再由主控根据整场数据固定面数/材质/贴图预算。不能无实测宣称“每个单位XX面就能支持500台”，也不允许单件无限堆料。优先共享材质、低成本标识和清晰轮廓，不靠大量透明材质或动态灯让物体可见。

## 7. 验收与并行方式

- 主控拥有项目配置、Main接线、共用fixture、地形/碰撞/导航/存档；美术只拥有分配的源文件、导出资源和manifest。不要两个agent同时编辑同一个 .blend、场景入口或资源注册表。
- ART-I00 主控确认后，地形样件与 U01/F01/F02 可以分开制作；共享材质由一个写者维护。
- 先在独立预览场景核查地面锚点、方向、比例；再在同一基准镜头下记录增量draw calls/内存/帧时。T2测量修复前只记录观察，不宣布性能通过。
- 不因导入成功就批量生产。第一批实际效果由所有者确认，技术成本由可复现数据确认。
