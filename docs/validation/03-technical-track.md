# T 线：用真实目标链决定引擎、AI 与性能路线

2026-10-03｜T-plan-1｜状态：**本轮未执行原生/模型/性能测试。**

输入：[技术总计划](../engineering/technical-validation-plan.md)、[超分专项](../engineering/upscaling-and-renderer-evaluation.md)、[逻辑约定](00-logic-readiness.md)、[共同 fixture](01-shared-fixture.md)。

主候选为 Godot 4 .NET+C#，不是先做四套引擎。只有发现不能合理局部解决的限制，并提供最小复现、profiler 与已尝试修复，才开同负载 Unity/URP 对照。

## T0：原生与接口风险先行

在所有者 M3 Pro/36GB Mac 核查实际系统、供电模式、工具与磁盘；只检查缺项，不把本说明当全系统安装授权。记录 Godot/.NET/导出模板/推理运行时的精确版本及来源。

先交一个最小可启动三维验证工程和本地保存样例，确认应用与全部原生依赖能走 arm64；编辑器在 Mac 上运行不是导出包原生证明。检查原生库、辅助进程、Steam 可选桥接；正式签名/公证凭据缺失可用开发构建继续，但签名/外部分发记 NOT_RUN。

统一米制坐标、资产锚点、碰撞/导航代理、稳定 ID 与状态桥。依赖由 T 唯一写入验证工程；A 获得导入约定。与最终游戏分目录，不先复制旧服务端、账号或 PostgreSQL。

验收：真实 .app 能启动，能加载和保存一个对象；不存在未说明的 Intel-only 必需依赖。此关只证明运行路径，不证明模型/规模通过。

## T1：独立模拟与真实目标链

以 S01-S05 建立最小领域动作和前置规划，不把“建阵列”硬编码成唯一脚本。运行物料净缺口、已知来源、设备能力、许可、施工/加工/运输，任务看板与场景消费同一状态。

先用规则/领域规划做明确标注的对照基线，单元测试状态与结算；不要为了高分只输出 TODO。完成判据是世界中的阵列建成、耗料和效果正确。

检查已知前置循环、无来源组件、重复承诺、共享前置取消、在途货物、暂停与读档。产出唯一性和存档恢复是硬门槛。不得把 catch-all 异常改为自动赠料救场。

## T2：地形、健康与救援

运行 S06-S11。比较至少一个轻量分阶段几何/局部形变方案；需要第二候选时按同一地块与操作对照，不直接做无限体素引擎。

地形渲染、碰撞、通行、安全区域和存档同源。记录地形更新范围与导航峰值，不全图每帧重烘焙。不让视觉清坡、规则仍挡路，或矿点回读后返矿。

电量和耐久分别模拟；出工、继续工段、回充、再次出工与拖运按真实预算检查。对照固定 10% 与动态预算，不把后者效果归功于尚未调用的分类器。零电/零耐久/双故障、充电排队与停电、救援者预算不足、暂停保存取消必须可复现。

## T3：AI 提供者的实际增益与边界

按能力分开评测：目标理解、前置规划、候选选择、文本表达。不要假设一种小模型适合所有职责，也不要把 Jev 绑定到某供应商或特定 API。

对照顺序：领域规划/规则基线→至少一个有明确许可和本地运行路径的分类器候选→确有必要时增加本地生成模型辅助。llama.cpp 是部分生成模型的候选运行时，不代表支持所有分类器。每个候选登记模型与量化 hash、许可、运行时、上下文、并发、峰值内存、失败处理。未获得大权重下载授权则停在对应项。

评测集包含正常/缺料/有在途/保护库存/工位竞争/中文否定和改目标/故障/不可达/晚到结果等。主控先封存留出变体和合格结果集合，调参线不读取；公开案例成功后再运行留出集。不同合法计划允许并存，不按匹配唯一自然语言答案评分。

必须分别报告：实际目标完成率、规划/执行失败、硬约束违规提案率、违规被拦率、合法但差的选择、回退率、p50/p95/p99 总延迟、用户需干预次数与错误成本。拦住错误是校验成功，不是 AI 任务成功；把规则结果包装成模型输出不算真实模型验证。

本地模式断网完成目标。关闭文本仍可读；模型故障已有安全任务继续。自然语言理解必须有否定/数量/授权检查。API 未获预算则只验证替身合同，真实 API 质量/费用/分发可用性仍为 NOT_RUN。

## T4：同一构建的联合负载与超分

先测 S，再 N，P 找后期拐点；场景包括真实生产/协作、健康变化、地形修改与本地推理，不仅是复制网格。S/N 跑通不保证 P 已通过。以 ×1/×2/×4 分别测实际模拟推进，若跟不上必须显式报告，不能静默变慢保持 FPS。

设备：D=M3 Pro/36GB 开发参考；L=实际较低配置 Apple Silicon，首选调查 M1/8GB 或明确同档设备；M=16GB 级对照。没有 L 就不能冻结商店最低配置。限制开发机内存或远程 Linux 跑分不替代 L。

初始画面目标沿用总计划：D 在 1920×1200 中档目标 60fps；L 在 1920×1080 低档目标 30fps。它们是试验目标非已确认商店规格。T0 先登记 p95/p99、反馈/规划延迟、模拟误差、内存压力和保存停顿的判定预算，再采成绩；第一次未达标可以改方案重测，不能只移动门槛称通过。

每条件建议预热 5 分钟、至少 3 次各 5 分钟稳态采样、一次 30 分钟联合长跑；这是实验协议而非开发工期估计。保存原始计时/CSV/日志和事件时间线，GPU/CPU 阶段分开分析。记录 build 类型、分辨率、温度/电源、资产/fixture/model hash，单列首次导入和冷启动。

先原生 100% 3D 分辨率、不开帧生成，比较 Metal 下 Forward+/Mobile 的功能与负载。然后仅对当前精确构建确实支持的 MetalFX/FSR 路径测等条件收益与画质；枚举/SDK 存在不等于能运行。官方当前表中 FSR2/TAA 为 Forward+，不可把它们写成所有渲染器共同开关。

检查摄像机移动、细支架、载荷变化、沙尘、地形突变后的历史残影及中文 UI。单列内部/输出分辨率、重建模式与真实基础帧时间；生成帧不计模拟吞吐。Windows DLSS/XeSS 后置评估，不为了品牌清单阻塞 Mac 验证。

## T5：平台与可维护性出口

核心规则/资源跨平台，路径/原生依赖/图形/推理后端集中适配。构建 Windows 样例或检查依赖可以提前做；没有真 Windows 设备则图形/性能/发行仍未验。缺 Steam 发行配置不阻止开发灰模，但不得宣称 Steam 集成完成。

形成一个主推荐 ADR，写清具体引擎版本、渲染器、地形方案、模拟边界、提供者/模型、降档方式、平台缺口和剩余风险。失败先给归因，不让所有者凭品牌选引擎。
