# 逻辑就绪检查：先收口执行约定，不再扩大产品讨论

> 历史快照（2026-10-03；2026-10-05整理）：保留当时计划与证据边界，不代表当前工程状态或自动开工授权。当前任务与执行合同以[双线TODO](../../TODO.md)及其链接为准。

2026-10-03｜V0-plan-1。

## 证据与判断

[决定登记](../decisions/decision-register.md) 已确认目标委托、工程授权、本地核心体验、Mac 原生、三维视角、地表改造、电量/耐久与救援。[返航补充](../product/energy-return-and-rescue.md) 已区分已确认规则和待验证算法。这些足以开始验证。

**审查结论（判断，非实测）：没有阻止验证开工的产品方向冲突；有若干跨系统接缝必须写明。** 以下“沿用”来自现役文件；“试验默认”是本次为小场景提出的约定，不能冒充所有者已批准的最终规则。实现发现与现役需求不相容时停在相关项，不擅自降产品范围。

## L01 时间、暂停与异步决定

沿用：模拟拥有时间和资产；模型延迟不能让世界乱结算。

试验默认：场景配置使用明确的模拟秒，记录模拟秒/真实秒的比例以及 1/2/4 倍速。V0 不依赖完整昼夜；压缩测试工作量不等于把整个日历乘 60。生产、电耗、天气和任务期限共用同一模拟时间口径。

暂停期间移动、工作、能耗、磨损和天气进程冻结；允许玩家编辑/取消计划。已开始的模型计算可以结束并排队，但暂停期间不得推进世界效果。恢复时重验相关计划、库存、区域和设备版本。模型超时采用墙钟，不能因为暂停而永不超时。

读档生成新的运行会话标识，旧会话晚到的结果不可提交；已接受的决定和实际进度从存档恢复，不重新生成覆盖。退出程序不补算离线生产。

## L02 接受目标、形成计划与获得权限

沿用：缺可获取材料不是直接拒绝目标的理由；超出批准范围需要玩家决定。

试验默认：目标先登记；区分核对中、可执行、待授权、待条件与完成。新增永久前置建筑只能在已批准的整体工程包内执行，否则先展示成本、占地和影响。正式开局与预置验证档分开，不能把预置加工/维修能力当成玩家已经亲手建成。

检测不可自举的前置循环、无来源物料、重复前置和并行资源竞争。搜索超时只代表本次未找到计划，不代表目标永远不可达或基地已失败。

## L03 机器人知道什么

试验默认：决策输入只包含已发现资源、当前可见条件与已收到预报；持有完整游戏世界数据的本地程序也不得向 NPC 泄漏未来脚本事件。分别测试有预警增耗和未预报突变。

真实已知风险由规则预算限制；分类器可以比较合法行动，不故意忽略风险来制造事故。未知突变仍可能造成停机。模型说明不反向生成矿点、配方、天气或资产。

## L04 材料、位置、承诺与取消

沿用：库存可用与预留分开；在途货物不等于入库；共享前置取消不能伤及其他目标。

试验默认：区分仓内可用、仓内预留、已承诺在途、现场货物和已消耗。可靠且未重复承诺的在途可减少计划净缺口，但到达前不能用于开工扣料。每个中间产出有唯一身份与归属；暂停、保存、重试不重复产生。

取消目标仅释放未执行义务与独占预留；真实地形变化、已生产材料、设备身份保留。共享前置重新分配归属。正在保护停机设备的恢复目标独立保留，不跟原建设目标一起删除。

## L05 回充和再次出工

沿用：正常约 10% 回充；零电原地停；恶劣环境可增耗；动态预算是待验证实现。

试验默认：以实际可达且可用的补能点计算移动、载荷、环境、等待与余量；继续工段还需包含该工段成本及结束位置的返程。比较固定 10% 基线与预算策略，后者不必使用大模型才能做算术。

恢复出工要足够支持下一安全工作段及回程，不写成到 11% 就反复离站。具体余量和恢复阈值由 fixture 明确，以迟滞或等价机制避免来回抖动；不在此冻结 80%/100% 等全局数值。充电位无电、满员或失联时不假设可立刻充电，队列不得永久饿死某台设备。

## L06 两种停机与救援

沿用：零耐久必须由其他有能力机器人送回维修，维修和充电互不替代。

**仅 V0 的闭环选择**：零电也采用“具备拖运能力的驮运送至补能点”；不同时实现现场充电、换电与多机吊装。一个具名驮运在 fixture 中配置拖运附件与载荷上限，不扩写为所有机器人天生都能救任何设备。零耐久回收后真实扣备件、耗时维修；电量不足继续真实补能，两项条件齐全才允许复工。

救援预算包含去程、连接/等待、带载回程与余量。救援者不足时保留任务、等待环境或请求调配，不生成已知危险的连环派遣。测试档预留可用恢复路径；不是给正式存档自动发放救援设备或免费补给。

## L07 地形、通行与资源来源

沿用：坡地整平、矿点开挖要真实且可保存；不强制任意体素世界。

试验默认：有限地块、阶段性几何改变。清坡/整平不自动产出金属矿；矿点产量只由同一资源规则扣减和入账，视觉阶段由真实开采状态派生。土方物流、挖洞和地下建筑不在 V0。

区域几何、碰撞与导航有一致的版本边界。更新期间标记受影响区域不可新规划穿越，或使用经过验证的安全旧路径；不得让已改变的碰撞与过期路线同时被当作可行。保存保留已提交地形状态，重载后完成必要重建再允许相关行动；取消工程不把土地还原成未动工状态。

## L08 本地能力、失败与人工控制

沿用：不使用 API 也应具有核心完整体验；玩家决定发展方向，不靠 AI 接管整局。

V0 的规则规划仅作为明确标注的基线，不冒充真实分类器或大模型。模型关闭对照不是本地 AI 验收通过。提供者切换不改变资源和权限规则；热切换取消旧请求，已接受计划不被重写。API 真实调用未获预算时只测隔离替身合同并标明 NOT_RUN。

暂不定义永久报废、强制删档和全局不可恢复失败判定。局部任务受阻要可解释；只有复核过的世界条件才可以称为无法恢复，不能用“规划没找到”代替证明。危机可观察，但安全场景不能被强制安排损失。

## 当前无需阻塞验证的事项

完整科技树、EA 体量/价格、多人宇宙、最终难度曲线、所有救援装备、精确磨损公式都可后续处理。正式生产前必须确认的事项是模型/资产分发许可、原生构建、存档恢复以及目标低配实测；它们不妨碍先做灰模和概念小样。

**不得冻结为最终决定的试验细节**：零电拖运方案、地图尺度、工作时长、环境倍率、余量阈值、恢复设施数量、压力档数量。每项须在试验报告中写明保留/修改建议与理由。
