# 电量返航、环境耗能与停机救援

版本：v0.4 补充｜日期：2026-10-03
状态：**所有者新增规则已确认；具体预算公式、阈值策略、救援设备和数值仍标为建议或待验证。**

本文件补充 [产品定义](product-definition.md) 与 [地表／机群保障](world-and-fleet-systems.md)。两份正文保留此前已核对内容；对“零电如何处理、零耐久如何恢复”的旧未决表述，以本文件为准。本文不是游戏已实现或技术已验证的证明。

## 1. 所有者本轮明确的设定

1. **电量归零：原地停机。** 移动也消耗电能，不能剩一丝电就无限走回基地。
2. **正常情况下，剩余电量约 10% 可以自行返回充电。** 这是常态回充参考，不是所有路线与天气下的安全保证。
3. **恶劣环境可以显著增加设备电耗。** 以火星沙尘暴为游戏内例子；原本足够返程的 10% 可能不再足够。环境影响、发生条件和倍率由内容规则定义，本文不把该设定当作现实火星物理结论。
4. **可以研究由 Jev 类有限决策能力判断何时返航。** 环境增耗后更早或更频繁回充，意味着有效作业时间和产出下降；不必每次都发生损毁才能产生经营压力。
5. **耐久归零：原地失去自身行动能力，需要其他机器人援助并送回维修。** 充电不能修复零耐久，现场停机不等于永久报废。

所有者消息中“游戏场景平缓”没有给出完整附加规则，本稿不据此推断难度曲线、事件频率或必须定期损坏设备。

## 2. 常态阈值与动态返航预算

### 2.1 产品承诺

玩家不必逐台安排正常充电；机器人应根据当前任务与可用补能条件维持续航。10% 用于常态行为的理解和基线测试，不应写死成“到 10% 才准返航”。

**建议默认**：约 10% 为常态回充基线，返程风险预算可触发更早回充。只使用当前可观察事实和已获得的环境预报，不赋予机器人对未来天气的全知。

### 2.2 预算建议，不是已冻结算法

比较剩余电量与“到达可用充电点的移动耗能＋到开始充电前的必要耗能＋安全余量”。评估继续当前工段时，还需计入该工段耗能，以及工段结束位置到充电点的返程成本。

候选因素：当前载荷、地形与坡度、实际可达路线、环境增耗、设备状态、充电点是否有电、接口是否兼容、排队期间的耗能、已占用的服务位。近的充电点不一定可用；已停电的站点不能作为默认安全目的地。

出工前、重要环境变化、通路改变、充电站失效和任务切换时重新核对。无需每帧或每个模拟 tick 调用模型。

示意：晴天相同工段可能在接近 10% 时回充；尘暴使预计返程消耗增加，就可能在更高电量时暂停工作返回。具体百分比由探针定，不在本文凭空指定 25% 或 40% 的固定新阈值。

### 2.3 Jev 类选择器的职责

代码提供可解释的能源预测与合法行动，选择器可比较“立即返航、完成安全短工段后返航、改去其他可用充电点、在允许位置避险或请求协助”等已实现候选。不能编造充电设施、自由修改电耗或用自然语言越过保护规则。

安全底线不依赖分类器可靠率：没有足够已知返程预算时，不把危险继续作业当作普通安全候选。玩家是否可以明确批准更高风险及其范围需单独设计，不能由模型擅自扩大。

超时、非法输出或模型不可用时采用已定义的保守处置，不因等待推理而继续消耗到零。保守策略也不能保证抵御一切未知事件；真实突变仍可能造成停机，并留下可追溯原因。

## 3. 零电和零耐久必须是不同故障

| 情况 | 当场行为 | 恢复边界 |
|---|---|---|
| 电量为零、耐久仍可用 | 停止自主移动与作业；位置、载荷、身份和任务保存 | 需要真实取得可用能源；是拖回充电、现场补能还是换电尚未全部冻结，不自动补电或传送 |
| 耐久为零、仍有电量 | 停止自主移动与作业，生成待回收／维修需求 | 由具有已实现救援能力的其他机器人送回可用维修位置；完成真实维修后还要检查电量 |
| 两者同时为零 | 同时保留两个原因，不相互覆盖 | 修复耐久不赠送电量，充电不修复耐久；恢复条件全部满足才可重返任务 |

停机期间不能完成运输入库、生产或施工。被其他单位拖运时，其位置可以随救援移动，但不能因此被标记为恢复自主工作。未授权的永久报废、消失、库存清空和强制删档不属于本设定。

## 4. 援助是可见且有成本的目标链

推荐链路：发现停机 → 登记恢复目标 → 评估可用救援者与回收路线 → 占用救援能力 → 到场连接／装载 → 运回维修点 → 排队维修 → 检查补能 → 回归任务。

哪类机器人能拖运、承载多少、是否需要专用附件或多机协作，仍待能力设计。不能默认为所有型号都能救援任何设备。

救援需要核查救援者去程、负载回程和安全余量，且考虑正在发生的恶劣环境。不能在第一台停机后无条件派第二台、再派第三台，形成因同一已知风险造成的无穷救援链。

合理的玩家决定可以是暂停高耗能生产腾出运力、调整恢复优先级、批准额外维修物资，或等环境缓和再执行已登记任务。系统给出明确的成本和后果，不用每个小动作重复审批。

维修位、备件和必要电力都有限。具有维修需求不等于立刻能修；在无已知合法路径时保留目标和原因。规划搜索没找到、模型超时或尚未勘探，不构成已经证明基地彻底失败。

## 5. 与原生产目标的衔接

机器人中断后，原目标不得丢失。保存已完成工段、未完成工作、已消耗与预留物资、载荷及承诺。可由其他合适机器人接手的任务，经交接与重新校验后继续，不重复扣料或重复计入产出。

货物仍在停机机器人或现场时，不得提前算作仓库可用；救援或交接只改变真实位置与保管关系。取消建设也不自动取消保护设备的安全恢复，反之取消一个恢复候选不得删除机器人的身份和物资。

读档恢复目标、故障原因、位置、载荷、救援占用和维修进度。已接受的决策不重新请求模型后覆盖，所有重放仍需防止重复世界效果。

## 6. 环境如何形成经营压力

建议把沙尘暴首先表现为真实参数变化与组织后果：工作和移动电耗上升 → 更早回充或更频繁轮换 → 有效生产时间减少 → 工程延后；继续冒险可能出现停机与救援支出。

不在这条后果链之外再无依据地重复扣同一笔“产量惩罚”。若尘暴还影响供电、通行或磨损，必须逐项定义来源与叠加规则，不从“恶劣环境”四个字任意推导全部负面效果。

AI 的价值是让玩家的授权被聪明执行，例如提前轮换、改变充电点或暂停远距作业。经营压力不靠让 AI 故意无视已知安全预算制造。

## 7. 场景与看板

场景可辨认“回充中、零电停机、机械故障、被拖运、维修中”。不同原因不只靠颜色区分。

目标卡说明当前影响，例如“阵列工程延后：一台筑垒正在回收维修；其余建材生产继续”。正常回充自动处理；只有超出授权或没有可执行安全方案时才请求玩家决定。

预测显示依据与不确定性，使用“按当前路线和环境预计”而不是保证式文案。一次停机应能追溯环境变化、返航决策、路由与余量，而不是只显示“AI 失误”。

| B01 | 晴天、充电点可达且有电 | 常态回充可自主发生；有基线阈值与实际耗能记录，不靠赠送电量 |

## 9. 尚未批准的细节

电耗倍率、磨损公式、精确安全余量、恢复到多少电重新出工、零电现场补能方式、救援装备、牵引载荷、维修成本、是否存在不可维修损毁、最终基地失败判据，均不得由本文件示例擅自冻结。

约 10% 常态回充、零电停机、零耐久需其他机器人送回维修是明确设定；动态预算与分类器的组合是建议的实现方向，两者要分别记录。
