# 地表改造、机器人保障与基地存续

版本：v0.1 基线＋v0.4 规则入口｜日期：2026-10-03  
状态：**产品新增约束已确认；下述实现范围和规则细节为建议，数值与失败条件待验证。**

**最新优先说明：**零电原地停机、常态约 10% 回充、天气增耗、零耐久需其他机器人送回维修，已经由所有者确认。具体规则与新增 B01–B08 验收见 [返航与救援补充](energy-return-and-rescue.md)。下文保留地表和保障基线；“援助细节待设计”不再意味着零耐久是否需要回收仍未决定。

本文展开产品主文档 C15–C17。不替代目标委托、玩家权限、本地完整体验及 Q04 不强制新手受损。

## 1. 玩家得到的不是临时动画，而是“这里被我改变过”

所有者明确要求：土坡可以清理并推平，矿点可以挖开，建设过的地方有材质或地形变化。

建议把变化分成三层，避免把昂贵但无意义的细节当成核心要求：

| 层 | 例子 | 持久性与规则 |
|---|---|---|
| 地形／场地事实 | 土坡削平、开挖坑、阻碍物移除 | 必须保存；对应占地、碰撞、坡度与可达性一致；低画质不能删除 |
| 作业表面事实 | 压实土、清理后的地表、已铺设的基底 | 随作业阶段保存；若对规则有影响，必须有明确字段与唯一来源 |
| 装饰表现 | 尘粒、短期履带印、碎屑动画 | 可以限量、淡出或降低画质；不能反推矿物产出、真实地形或任务进度 |

改变地形与留下灰尘，不是同一种效果。仅放一张平地贴图、仍保留原有土坡碰撞，不符合产品承诺。

## 2. 建设地块的目标链

候选状态：原始地貌 → 计划改造区 → 清场中 → 整平中 → 合格基底 → 安装／施工 → 已建成。

这些是产品上的可辨阶段，不强制每一阶段都引入一套新资源。具体工序可按工程合并，但需要工作量、设备能力、时间和能源的真实承载。

提交目标时：标清改造区域、会移除的对象、预计额外成本及相关风险。工程托管可一次授权整条链；扩大范围、拆除既有设施或影响受保护通路时需再授权。

执行时：场地几何按实际进度或已定义的阶段更新。能够解释何时封闭施工区、何时可以通行；不能让其他机器人穿过尚未清除的土坡，也不能因可视层更新先于碰撞而掉进地形。

结束或取消时：已发生的改造保留。取消建设不把被削掉的坡、挖出的矿或完成的基底瞬间恢复原状。之后是否提供回填或重整地面，应是独立任务与成本。

## 3. 矿点开挖

建议第一批以有限矿点和几档可读的开采形态验证：地表迹象 → 露出矿层 → 明显开采面／坑 → 资源减少后的状态。

外观阶段与权威矿点状态关联，不要求“每采一单位矿就生成一个坑”。矿量、现场货物、已送达物资分别核算；形变不能再次发放资源。

开挖影响通路时，剩余任务必须重新核对可达性。存档恢复要同时恢复矿量、地形和计划；不能刷新后矿量保持减少、画面却恢复未开采的原状。

**建议首批范围**：一处小土坡、一块施工区域、一处可开挖矿点。不是只有无碰撞变化的装饰，但也不承诺任意体素雕刻、地下洞穴、地质力学或整星球改造。产品要求先固定，技术方案在验证中选。

## 4. 机器人不是无限劳动单位

已确认：每台机器人有耐久，会耗电，需要充电和维修。能力可智能组织，但不能凭空恢复。

| 概念 | 必须区别 | 建议的正常处理 |
|---|---|---|
| 电池电量 | 可用于移动／作业的当前能源 | 在可达、可用、有电的充电点补能，真实耗时与耗能 |
| 电池容量 | 能存多少，不等于现在存了多少 | 容量升级不自动赠送电量；老化是否影响容量待设计 |
| 耐久／健康 | 机械损耗，不因电池充满而消除 | 在具备能力、备件、工位和必要电源时维修 |
| 任务承诺 | 当前目标对设备时间和资源的占用 | 换班／回充／维修需交接，不丢在途货物、不双重分配 |
| 永久损毁 | 与零电、低耐久、停机不同 | 尚未批准具体机制；不能静默添加永久报废或不可撤销删档 |

出工前建议检查：工作预计耗电＋去往可用补能点所需电量＋安全余量，以及任务期内的健康风险。不能只看电量是否大于零。

安全余量、磨损曲线、每次维修成本和修复上限均待数值探针。不要照搬旧版功耗，也不把模型推理成本映射为机器人耗电。

## 5. 保障也是目标系统的工作

推荐把“为工程维持所需运力／维护能力”作为目标的保障依赖，而非让玩家逐台点击保养。

机器人到达正常阈值时，系统在已授权范围内安排回充、维修、换班与备件生产。例外才提交给玩家：备用物资被保护、需要新建维护站、借调会打断保护任务、恢复计划超预算。

充电位、维修位、机器人和备件都属于有限能力。需处理排队、公平性、优先级和过期请求；不能两台机器占用同一个唯一服务位，也不能低优先级机器人永远抢不到维护机会。

维护计划不能与生产计划互相无限扩张：生产备件需加工机，加工机维修也需备件时，要识别自举前提，提前保留真实恢复能力。仅列出更多 TODO 不算解决死锁。

玩家设置保护库存与关键设备后，AI 应说明对工程的影响，不能为“完成任务”偷偷动用最后一份维修物资。

## 6. 生存感来自经营后果，不来自故意制造的 AI 失误

已确认的风险：资源失管可能让基地失去维持能力。

候选风险链：扩建优先 → 备件与充电容量被挤占 → 可用设备下降 → 采集和加工能力下降 → 恢复所需材料无法再获得。这一链应可被观察和追溯；不是强迫所有玩家经历的事件。

建议区分：

- **受压但可恢复**：限电、暂停扩张、回收已知物资或调整队伍即可恢复。
- **需要决策或新条件**：现权限内无法恢复，但存在待批准动作或尚未知情报。
- **基地不可继续维持**：在当前定义的有限规则与可用能力下，确证没有恢复路径。失败触发细则需专项冻结。

规划器超时、模型输出非法、尚未探索、某个候选搜索没找到，都不能单独证明基地已经“死了”。

### 与 Q04 的关系

Q04 保证的不是“玩家永远不会失败”，而是“不用强制新手受损来证明玩法成立”。可以提供正常可持续的开局、清楚的风险提示和默认保守保障，同时允许经过告知的冒险和长期资源失管导致失败。

不隐藏白送资源救场；也不把用户尚未确认的永久死亡、铁人模式、每场必败、自然时间持续扣耐久写成默认规则。关闭游戏不推进电量或耐久，暂停不继续磨损。

零耐久需其他机器人送回维修已经确认；援助设备、成本、零电补能方式、读档与难度的细则仍需专项设计。不得将“送回维修”解释成无成本传送、自动返航或自动恢复全部状态。

## 7. 场景与看板怎么呈现

默认场景要能看见：工程区正在整平、矿点打开、机器人卸货、充电等待、维修中和停机。状态不能只靠色差；图标、姿态、动作和简短说明互补。

看板以目标为主，保障任务按需展开。例如“阵列工程：建材生产中；两台驮运轮换补能；一台筑垒检修；无需你决定”。真正要用户介入时，解释会失去什么、有哪些选择。

低画质应保留这些信息，不以关闭停机标识或地形变化实现帧率目标。
